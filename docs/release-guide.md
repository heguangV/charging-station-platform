# NCS 发布指南

| 项目 | 内容 |
| --- | --- |
| 发布来源 | 审核并回归通过的 `develop` |
| 发布目标 | `main`，通过 Pull Request 合入 |
| 版本格式 | `v主版本.次版本.修订号` |
| 更新日期 | 2026-09-02 |

## 1. 发布门禁

- SRS 追踪矩阵中本次范围没有“未实现却标为完成”的条目。
- Debug 与 Release 构建、相关测试、三个可执行目标烟雾测试和仓库检查通过。
- 数据库迁移按顺序验证新建、升级、失败回滚和隔离恢复；已发布迁移没有被修改。
- 公开 DTO、路由、错误码、状态与 WebSocket 事件通过契约测试并完成兼容性评估。
- `.env`、密钥、数据库、日志、备份、模型训练数据、截图隐私和构建产物未进入提交。
- 配置变化、部署步骤、已知限制与回滚步骤均已审核。

## 2. 发布流程

1. 冻结本次范围，更新 `CHANGELOG.md` 的“未发布”内容和需求追踪状态。
2. 在 `develop` 执行 `./scripts/configure.sh release`、构建、测试、烟雾测试和检查。
3. 使用隔离数据验证迁移、备份恢复、进程重启和活动充电恢复。
4. 创建 `develop` → `main` Pull Request，至少一名其他成员批准且全部状态检查通过。
5. 合并后创建带注释标签和发布说明；不得重写或强推已发布历史。
6. 按运行手册部署，检查 live/ready、客户端连接、日志、数据库版本和关键只读查询。
7. 观察窗口结束后记录结论；异常达到回滚条件时立即执行回滚。

## 3. 回滚原则

应用程序可回滚到上一已验证版本；数据库只使用事先设计并测试的前向修复或已验证备份恢复。存在不兼容数据写入时，不得仅替换二进制。回滚前冻结新写入，保留现场，记录版本与数据库 schema；回滚后重新执行就绪检查和关键数据核对。
