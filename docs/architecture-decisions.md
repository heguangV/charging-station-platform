# NCS 架构决策记录

## ADR-001：服务端是唯一业务与数据库边界

- 状态：已接受
- 日期：2026-09-02
- 依据：SRS 架构约束、`NFR-S-03`

Qt 客户端和 Dashboard 只访问 HTTPS REST / 鉴权 WebSocket；只有 `ncs_server` 的数据访问层打开 SQLite。这样集中事务、幂等、权限和审计，避免多进程直接写单文件数据库造成状态分叉。代价是本机部署也依赖服务端可用，因此客户端必须提供明确的连接失败与恢复状态。

## ADR-002：公共领域层不依赖 UI、Crow 与 SQLite

- 状态：已接受
- 日期：2026-09-02

`core` 保存错误码、领域值、状态机和应用边界；协议转换位于 `server/controller`，持久化位于 `infrastructure/sqlite`。依赖方向为可执行程序/适配器 → 应用/领域，不允许反向依赖。该决策用于保持单元测试速度和跨平台能力。

## ADR-003：业务单位使用整数和 UTC Unix 秒

- 状态：已接受
- 日期：2026-09-02
- 依据：SRS `BR-09`

金额与价格使用整数分，电量使用整数毫瓦时，时间使用 UTC Unix 秒。显示层负责换算为元、kWh 和本地时间。禁止在业务与数据库边界使用浮点金额，避免累计舍入差异。

## ADR-004：配置由环境覆盖文件，正式环境强制 TLS

- 状态：已接受
- 日期：2026-09-02

进程环境变量优先于 `.env` 文件；`.env` 只用于本地且不入库。正式环境拒绝明文 HTTP，并要求显式证书与私钥路径。安全摘要只输出环境、监听地址和传输模式，不输出凭据与内部数据路径。
