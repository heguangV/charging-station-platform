第一章 引言

1.1 编写目的

本测试计划用于指导 NCS 充电桩管理平台的测试活动，明确测试范围、策略、资源、进度与风险，为单元测试、数据库测试、契约测试、集成测试、UI 测试、端到端测试及非功能测试提供统一依据。本计划覆盖仓库已有的 41 项 CTest 注册测试的回归，并针对[需求追踪文档](requirements-traceability.md)列出的验收欠账（用户端真实联调、管理端 UI、大屏前端、客户端性能、严格单机部署、安卓真机验收）安排专项验证。本文档供测试组、开发组及指导教师评审与跟踪。

1.2 项目背景

NCS 是覆盖 **用户服务 → 设备运维 → 数据存储 → 决策分析 → 智能预测** 全链条的充电桩管理平台，采用分层架构：

- 用户层：`ncs_user`（Qt Widgets 竖屏用户端，420×760）+ `ncs_admin`（Qt Widgets 管理端，最小 1280×800）+ `apps/mobile`（Qt Quick 安卓实验端）
- 服务层：`ncs_server`（Crow，HTTPS REST + WebSocket，默认端口 8443），承载鉴权、事务、设备模拟、持续计费、排队调度、到期处理与实时通知
- 数据层：SQLite 3 单文件 `charge_platform.db`（28+ 表、v1→v9 迁移），仅允许服务端数据访问层打开
- 可视化层：`apps/dashboard`（Vue 3 + ECharts 运营大屏，1920×1080 基准）
- 智能层：`ml/`（Python + scikit-learn 负荷预测，固定随机种子 `20260901`）
- 增强层：`tools/device_link_sim`（UC-X-01 充电桩设备通信模拟器，独立 CMake）

客户端只通过 `/api/v1` REST 与鉴权 WebSocket 访问服务端，不直接打开 SQLite；金额整数分、电量整数毫瓦时、时间 UTC Unix 秒是全局数据约束。第一、二阶段（工程基础、数据与领域）与第三阶段（服务端通信）已按追踪矩阵完成，本计划在已有 CTest 分层测试基础上，把验收重心放在尚未闭环的真实联调与 UI 证据上。

第二章 测试必要性说明

2.1 业务价值

- 需求追踪文档明确列出了当前验收欠账：用户端真实服务端联调与 UI 证据、管理端部分界面（独立状态表、订单历史、UC-A-09 管理界面）、大屏设备占比口径与受权快照、NFR-P-01/P-03 客户端性能、NFR-D-02 严格单机部署、安卓真机验收、ML 训练/评估质量。没有一轮按计划执行的测试，这些"部分完成"无法转为"完成"。
- 避免重复劳动：仓库已有 41 项 CTest 测试覆盖数据库、契约、集成与烟雾层，本计划划定"回归已有 / 补测欠账"的边界，防止各成员重复写同层用例、遗漏未覆盖路径。
- 计费、排队、结算全部走状态机与事务，金额按整数分换算，任何回归都可能直接造成账目错误，需要状态迁移法设计的用例集而非随机点测。
- 腾讯地图、ML 子进程、摄像头等外部依赖存在多级降级，需要提前约定可量化的降级验收标准，减少"看起来能用"的主观争议。

2.2 质量门禁

- 单项需求关闭：正常流、异常流、权限和边界均有测试证据，且构建、CTest 相关用例、烟雾测试、`git diff --check` 全部通过（研发指南 §8 完成定义）。
- 阶段发布/演示前：P0 用例通过率 ≥ 95%，无未关闭 P0/P1 缺陷。
- 主链路必须可自动化回归：免密登录 → 选桩/排队 → 报价确认 → 预约 → 开始充电 → 实时计费 → 结算 → 订单小票（`UC-U-01`、`UC-U-06`~`UC-U-10`）；数据库迁移 v1→v9 升级保数据。

2.3 协作价值

- 禅道缺陷按 CTest 层级标签（`unit` / `database` / `contract` / `integration` / `ui` / `e2e` / `nonfunctional`）分类，回归范围可裁剪。
- 需求变更时通过 RTM 与九列需求矩阵快速识别受影响用例；数据库迁移、错误码、WebSocket 事件变更必须先同步接口文档与契约测试再改实现（研发指南 §7.2）。

3.2 不纳入或低优先级范围

- 真实充电桩硬件、真实 GPS、真实短信网关、真实支付网关 — 全部使用项目内模拟机制验收

- Windows 原生运行验收 — 保持源码构建能力（`NFR-C-01` CI 检查），不作为本计划验收项
- 大规模 ML 模型升级（LSTM / LightGBM）— 接口兼容性冒烟即可
- UC-U-11 拍照头像摄像头采集 — 实现未开始，仅验收已有头像 REST 链路与无设备降级路径，摄像头部分待实现后另立专项

4.2 测试设计方法

等价类划分、边界值分析、场景法、状态迁移、错误推测。本项目专项强化：

- 状态迁移法：活动流程 10→90 全部合法迁移与非法迁移拒绝；设备空闲/使用中/故障/重启中/已停用切换
- 边界值：充值 0.01 / 10000 元、余额起充门禁 5.00 元、头像 5MB、昵称 1~20 字符、评价 1~500 码点、经纬度合法范围
- 并发与幂等：同一电桩并发占用（BR-03）、重复取消/结算重放、`Idempotency-Key` 重放
- 数据库专项：v8→v9 升级保数据、损坏库三类错误路径、连接线程归属、迁移并发
- 降级注入：腾讯地图超时/无 Key/空折线、ML 子进程超时、摄像头缺失

4.3 通过 / 失败准则

入口准则

- `./scripts/configure.sh dev`、`./scripts/build.sh dev` 成功，烟雾测试通过
- 测试数据库、日志、截图使用隔离目录，不触碰开发与演示数据（tests/README.md 约定）
- 测试账号、模拟验证码、地图 Key（或降级注入方案）就绪
- 用例编号与 RTM 已评审，每条用例关联 `UC-*` / `BR-*` / `NFR-*`

出口准则

- P0 用例通过率 ≥ 95%
- 全量 CTest 通过，`./scripts/smoke-test.sh` 通过，`./scripts/check.sh` 通过
- 充电主链路端到端（真实服务端 + 真实客户端）跑通并归档截图/日志
- 非功能已验收项（`NFR-P-02/P-04/P-05` 等 8 项阈值）回归通过
- 禅道 P0/P1 缺陷清零或经评审延期，且欠账项在 RTM 中状态如实更新

失败准则：任一 P0 用例失败且阻断主链路（无法登录、无法结算、数据丢失），立即停止新用例执行，按缺陷流程闭环后回归。

4.4 回归策略

- 每次提交：CI 构建 + 全量 CTest + `check.sh`
- 缺陷修复：关联用例单条回归 + 对应层级标签用例抽查
- 数据库迁移、公开 DTO、路由、错误码或 WebSocket 事件变更：必须先更新契约测试，再跑全量 `contract` + `database` 层
- 发布前：按[发布指南](release-guide.md)执行 P0 全量 + 烟雾测试 + 备份恢复抽查（`NFR-R-03` 7 份日备 / 4 份周备）

第八章 资源与风险

8.1 人力资源

4~5 人小组，角色见第五章；每日站会 15 分钟同步阻塞项；RTM 用例按人认领，避免漏测。

8.2 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 并发状态机缺陷导致用例 flaky | 同一用例时过时不过 | 测试隔离目录 + 结束重建测试库；服务端冲突重试 3 次的断言固定化；flaky 用例先降级为 P1 并登记 |
| 腾讯地图 Key 缺失或网络受限 | 导航用例阻塞 | 按三级降级设计用例：注入失败→断言浏览器入口与 Haversine 距离；主链路用例不依赖地图 |
| 时间加速倍率引起计费断言抖动 | 费用断言误差 | 固定 `charge.time_scale`，断言用整数分/毫瓦时精确换算，禁止浮点近似 |
| VM 资源不足导致压测失真 | 非功能结论不可信 | 固定 2核/4G 规格、记录基线环境、虚拟客户端复用 `tests/performance/` 既有阈值 |
| 欠账范围大（UC-A-09 界面、UC-U-11、安卓真机） | 进度与结论混淆 | 未实现项标记"阻塞"而非"失败"；每项欠账在 RTM 保持原状态，不因测试计划虚标完成 |
| 测试数据污染演示库 | 演示环境账目错误 | 强制独立测试数据库文件；`scripts/clean-runtime-data.sh` 清理；测试账号不用于演示 |

第九章 缺陷管理与报告

9.1 缺陷等级

- 致命：主链路不可用（无法登录、无法创建/结束充电、结算数据错误、数据库损坏丢数据、服务端崩溃）
- 严重：鉴权或越权失效、幂等失效产生重复记录、事务不回滚、金额/电量换算错误、敏感信息泄露（完整手机号、SQL、内部路径）
- 一般：状态显示错误、降级提示缺失、非主路径异常、文案与界面尺寸偏差
- 建议：易用性与界面改进

9.2 缺陷必填字段

标题、复现步骤、期望/实际、环境（提交/构建 + 环境变量）、测试层次（对应 CTest 标签）、关联 case_id、关联 `UC-*`/`BR-*`/`NFR-*` 需求ID、截图/日志（统一含 UTC 时间、级别、模块、请求 ID，已脱敏）

9.3 测试报告（周报模板）

1. 本周执行用例数 / 通过数 / 通过率（按 P0/P1 分列）
2. 新增/关闭缺陷统计（按等级与测试层次）
3. 风险与阻塞（含标记"阻塞"的未实现项）
4. 下周计划与需协调项（如地图 Key、真机设备、VM 资源）
