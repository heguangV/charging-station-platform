## 1. 使用规则

本文是项目唯一的日常研发指南，用于回答“开发什么、如何拆分、按什么顺序完成、何时算完成”。

- 软件需求规格说明书（SRS）是最低验收基线；实现具体功能时必须读取对应的 `UC-*`、`BR-*` 和 `NFR-*`。
- 本文只记录可直接执行的要求，不保留问答过程、方案比较或历史状态。
- 本文与 SRS 表述不一致时，采用能够完整覆盖两者的更严格要求；无法同时满足时以 SRS 为准。
- 技术替换必须保留原功能、异常处理和可观察结果，并提供测试证据。
- 需求文档描述目标状态，不代表功能已经实现；完成状态以代码、测试和验收记录为准。

文档中的“必须”“不得”表示强制要求，“应”表示无充分理由时必须遵循的推荐要求。

## 2. 产品目标与范围

NCS 是一套用于课程实训、团队研发和功能演示的电动汽车充电桩管理平台。系统使用模拟充电设备、虚拟余额和模拟支付，不连接真实电力设备，也不处理真实资金。

当前交付由五部分组成：

| 子系统 | 技术形态 | 核心职责 |
| --- | --- | --- |
| 车主用户端 | Linux Qt Widgets + C++，固定 420×760 | 登录、地图、资料、钱包、排队、预约、充电、结算和订单 |
| PC 服务器管理端 | Linux Qt Widgets + Qt Charts + `QTcpServer` | 管理、监控、设备模拟、实时消息、统计和预测展示 |
| 数据层 | SQLite 3 + Qt SQL | 账号、站点、设备、流程、订单、钱包、日志和预测数据 |
| 数据大屏 | Vue 3 + ECharts，1920×1080 | 运营指标、设备状态、趋势和预测可视化 |
| 智能分析 | Python 3.10+ + scikit-learn | 数据准备、RandomForest 训练、评估和预测 |

当前交付不包含真实充电桩协议、真实短信、真实支付、退款、优惠券、电子发票、厂商推送、固件升级、Android/iOS 正式客户端、应用商店安装包、Windows 安装包、PostgreSQL 公网服务和复杂深度学习模型。

## 3. 运行与部署边界

- 开发与验收环境为 Ubuntu 22.04+，当前使用 Ubuntu/Qt 6.8.3 验证。
- 桌面 C++ 最低兼容 Qt 6.5.3、GCC 11+、MSVC 2019/2022 和 C++17。
- 严格验收时，`ncs_user`、`ncs_admin` 和 `charge_platform.db` 在同一 Ubuntu VM 中运行。
- VM 使用 NAT；跨机器部署不属于当前交付，任何远程模式都不得通过网络共享目录直接访问 SQLite 文件。
- 用户端窗口固定为 420×760；管理端最小尺寸为 1280×800；数据大屏基准尺寸为 1920×1080。

## 4. 用户与权限

| 角色 | 权限 |
| --- | --- |
| 车主用户 | 管理本人资料、钱包、排队、预约、充电和订单 |
| 运营管理员 | 管理站点、设备、用户、订单、价格、模拟运行、统计和预测 |
| 决策查看者 | 只读访问数据大屏，不执行任何写操作 |

权限必须由公共业务服务层和 PC 服务器端校验，不能只依靠界面隐藏按钮。

## 5. 用户端业务指南

### 5.1 账号、登录与资料

- 注册需要唯一用户名、唯一的 11 位手机号和密码。
- 正式登录支持“用户名 + 密码”和“手机号 + 密码”。
- 为完整覆盖 SRS，开发与验收配置还必须提供手机号模拟验证码登录/自动注册流程：验证码为 6 位，有效 10 分钟，最多错误 5 次，60 秒内不能重复获取，新码使旧码失效。
- 模拟验证码只显示在当前本地界面，不写入日志；只有已绑定手机号的用户可使用验证码重置密码。
- 普通用户会话最长 30 天且最多保留 3 个桌面终端；管理员最多 2 个终端，超限时撤销最早会话，退出和注销立即撤销相关会话。
- 新用户余额为 0，默认昵称为“用户 + 手机号后四位”，头像为空时显示默认灰色头像。
- 用户可修改昵称和头像；头像必须校验真实格式、大小和尺寸，重新编码后保存到 `QStandardPaths` 确定的共享数据目录。
- 手机号展示时隐藏中间四位。
- 冻结用户不能登录或创建新充电流程；欠费用户可登录、查看和充值，但不能创建新流程。
- 注销必须立即撤销会话并匿名化用户名和手机号；头像在 24 小时内删除，匿名订单、钱包和充电记录保留 3 年，审计/运维日志保留 180 天，匿名 ML 聚合数据保留 1 年。

### 5.2 地图、站点与导航

- 当前业务范围为北京，预置 5 个演示站点和 48 台设备。
- 用户可通过区域或地址确定位置，系统计算站点距离并按距离排序。
- 站点卡片显示名称、总单价、空闲数/总数和距离；详情页显示地址、营业时间、价格拆分及设备列表。
- 距离必须支持 Haversine 本地计算，不能把地图服务作为列表可用性的唯一前提。
- 腾讯地图为主地图服务：客户端使用受来源和配额限制的 JS Key，WebService Key 只允许 PC 服务器端读取。
- 地图或网络不可用时必须显示预置坐标、站点列表和明确的降级提示；导航可降级为系统浏览器 URL。

| --- | --- | ---: | ---: | ---: | ---: |
| NCS 中关村充电站 | 海淀区 | 10 | 0.85 | 0.50 | 1.35 |
| NCS 朝阳公园充电站 | 朝阳区 | 12 | 0.90 | 0.55 | 1.45 |

### 5.3 排队、预约与充电

- 一个用户最多存在一个活动充电流程，一个设备最多被一个活动流程占用。
- 有兼容空闲设备时直接预约；预约有效期为 15 分钟。
- 无空闲设备时按“站点 + 快充/慢充类型”进入即时队列，用户不指定具体设备。
- 设备释放后按入队顺序分配最先可用的兼容设备；轮到用户后生成 5 分钟有效的最终报价。
- 用户确认报价后创建预约；拒绝、取消或超时不收费，并立即释放资源、递补下一位。
- 排队、报价确认和预约取消必须幂等，重复请求不得重复释放或递补。
- 充电前必须检查账号状态、欠费、最低余额、流程唯一性、设备状态和预约归属。
- 全市最低起充金额为 5.00 元；预约和开始充电前的可用余额不得低于该值。
- 充电默认时间倍率为 60，可由管理端在 1～300 范围内调整；倍率变更不影响已经开始的会话。
- 用户可手动结束，也可设置目标金额或余额上限自动结束。
- Socket 断开后由 PC 服务器端继续计费；重连后根据 SQLite 中的真实状态恢复充电页或结算页。

| 状态码 | 名称 |
| ---: | --- |
| 10 | `QUEUED` |
| 20 | `QUOTE_PENDING` |
| 30 | `RESERVED` |
| 40 | `CHARGING` |
| 50 | `SETTLING` |
| 60 | `COMPLETED` |
| 70 | `CANCELLED` |
| 80 | `SETTLEMENT_FAILED` |
| 90 | `EXPIRED` |

### 5.4 价格、钱包与结算

- 价格由行政区基础电费和基础服务费组成；排队压力只调整服务费。
- 排队压力定义为“等待人数 ÷ 当前可运营的同类型设备数”，故障、停用和重启中设备不进入分母。
- 排队压力每 5 分钟计算一次：`≤0.5` 不调整、`(0.5, 1]` 上浮 10%、`(1, 2]` 上浮 20%、`>2` 上浮 30%；压力下降时自动回落。
- ML 只提供未来 1/6/24 小时的调价趋势和建议幅度；建议范围为 -20%～+20%、步长 5%，运营管理员确认 1/6/24 小时有效期后才可生效。
- 最终服务费按“区域基础服务费 ×（1 + 排队调整比例 + 已批准 ML 调整比例）”计算，并限制为基础服务费的 80%～140%；所有调价必须记录原因、操作者、生效时间和前后值。
- 直接预约时保存价格快照；排队用户在最终报价生成时锁定价格，后续配置变化不得修改活动流程和历史订单。
- 金额在 SQLite 中使用整数分，电量使用整数毫瓦时；界面按元、kWh 和两位小数展示。
- 结算、余额扣减、欠费、钱包流水、设备释放和统计更新必须在同一事务中幂等完成。
- 充值为虚拟充值；存在欠费时先清偿欠费，剩余金额进入余额，并分别生成不可变流水。

## 6. PC 服务器管理端指南

- 管理员密码必须使用专用密码哈希；开发账号 `admin/123456` 只能存在于开发配置和种子数据中。
- 主界面提供营收、设备状态、站点、充电桩、用户、订单、运维、价格和预测模块。
- 营收展示近 30 天折线图、柱状图和统计指标；设备状态展示可识别配色、数量和占比。
- 站点、设备和用户支持查询、新增、修改、逻辑停用以及异常提示；存在关联设备的站点不得删除。
- 设备状态至少覆盖空闲、使用中、故障、重启中和停用。
- 远程重启必须二次确认并记录原因。充电中设备需要先停止计费、幂等结算或生成待处理结算，再通知、审计和模拟重启。
- 管理端承载 `QTcpServer`、设备模拟、持续计费、排队调度、到期处理、实时通知和统计导出。
- 运营管理员可查看大屏；决策查看者只读访问大屏数据。

## 7. 数据库与一致性指南

- 主数据库为 SQLite 3 单文件 `charge_platform.db`，由同机 `ncs_user` 和 `ncs_admin` 通过公共数据/服务层访问。
- 任一程序首次启动时必须在进程间初始化锁保护下完成 schema、迁移和演示种子；后续使用 `schema_version` 升级，已执行迁移不得修改。
- 数据表至少覆盖用户、管理员、角色、会话、验证码、站点、设备、活动流程、订单、充值、钱包、欠费、设备命令、日志、备份、预测和模型版本。
- 两个进程分别使用专用数据库工作线程和独立连接，启用外键、WAL 和 `busy_timeout`。
- UI 层不得包含 SQL；查询必须参数化，跨表写操作必须使用事务。
- 设备分配和结算使用 `BEGIN IMMEDIATE`、条件更新、唯一索引及幂等键；并发冲突最多重试 3 次。
- 数据库打开失败、损坏、版本不匹配、锁超时和事务失败必须明确提示，不得崩溃或静默丢数据。
- 开发、测试和演示使用不同数据库文件；数据库、日志和备份不得提交到 Git。

演示数据使用固定随机种子 `20260901`，生成 300 个模拟车主、约 9,000 个订单、约 900 条充值记录和连续 90 天的五站小时数据。

## 8. Socket、并发与通知指南

- `ncs_admin` 使用 `QTcpServer`，`ncs_user` 使用 `QTcpSocket`。
- 消息帧格式为“4 字节网络序长度 + UTF-8 JSON”，包含协议版本、请求 ID、消息类型、时间和数据。
- 协议必须限制最大帧长度，正确处理拆包、粘包、超时、异常断线、幂等写操作和稳定错误码。
- 断线后自动重连，并从 SQLite 获取完整状态快照，不能只依赖丢失前的增量消息。
- SQLite 访问使用专用 `QThread` 工作对象；CPU 密集或批处理任务使用 `QThreadPool`；Socket 使用 Qt 异步事件；ML 使用 `QProcess`。
- 后台任务不得直接操作 UI，数据库、网络、文件和 ML 工作不得阻塞 UI 或服务器事件循环。
- 排队分配、最终报价和预约到期使用 Socket 站内通知；通知不得包含手机号、余额或完整订单等敏感数据。

## 9. 数据大屏与机器学习指南

### 9.1 数据大屏

- 管理端或 Python 每 30 秒从 SQLite 聚合并原子替换版本化 `dashboard.json`；大屏按相同周期拉取。
- 大屏展示总营收、设备、站点、用户、订单趋势、状态分布、地图和预测结果，并显示数据截止时间。
- 无数据返回空集合；无法计算的值使用 `null` 并说明原因。生成失败时保留最近成功文件并显示过期状态。
- 大屏不得直接打开或写入 SQLite。
- 鉴权和角色权限由 PC 服务器端校验，不能公开匿名访问运营数据。

### 9.2 机器学习

- 使用连续 90 天小时数据、时间特征、天气、节假日、站点和历史滞后特征训练 RandomForest。
- 数据按时间切分；固定随机种子；缺失值处理、特征顺序和模型参数必须可复现。
- 评估必须输出 MAE、RMSE 和 MAPE；MAPE 只计算真实值大于 0 的样本并报告排除数量，可额外输出 WAPE。
- 模型必须在固定测试集上优于朴素基线才能通过验收；未通过时页面可使用基线保持可用，但不得生成 ML 调价建议或标记 ML 完成。
- 同时最多执行一个训练任务和一个预测任务，超时分别为 10 分钟和 2 分钟。
- 失败时保留最近成功结果并标记过期；模型保留 30 天，预测和评估历史保留 90 天。

## 10. 非功能与安全标准

- 不超过 100 个站点时，列表加载和渲染小于 500ms；30 天营收聚合小于 300ms。
- 充电页每秒刷新，在目标设备上 CPU 占用原则上小于 5%。
- 容量目标为 3,000 个注册账号、100 个同时在线 Socket、50 个同时排队流程和 48 个同时充电会话。
- Socket 服务持续处理 20 请求/秒，并承受 50 请求/秒短时峰值。
- 所有失败操作必须提供明确文字提示，并具备加载、空数据、失败和恢复状态。
- 源文件使用 UTF-8；MSVC 使用 `/utf-8`；路径通过 Qt 跨平台 API 构造。
- 单个手写源文件不超过 400 行。
- 密码、令牌和验证码只保存安全摘要；完整手机号、令牌、验证码和密钥不得写入日志。
- 日志写入 `logs/ncs_YYYYMMDD.log`，包含时间、级别、模块和请求 ID；应用日志保留 30 天，审计/运维日志保留 180 天。
- SQLite 使用在线备份 API 或 `VACUUM INTO` 创建一致性快照，每日保留 7 份、每周保留 4 份，并至少执行一次恢复测试。
- 备份恢复目标为最多丢失 24 小时数据，并在 4 小时内恢复服务。
- 容量与并发测试使用独立测试数据库和 Python `asyncio` 虚拟用户，不依赖真实车主。

## 11. 目标工程结构

```text
apps/
├── user/                  Qt Widgets 车主用户端
├── admin/                 Qt Widgets PC 服务器管理端
└── dashboard/             Vue/ECharts 数据大屏
core/
├── domain/                实体、值对象和状态机
└── application/           用例、服务接口和权限边界
infrastructure/
├── sqlite/                schema、迁移、仓储、事务和备份
├── map/                   腾讯地图与本地距离计算
└── files/                 头像、日志和快照文件服务
ml/                        数据准备、训练、预测和评估
tests/                     单元、集成、协议、并发、恢复、UI 和端到端测试
docs/                      SRS、研发指南和专项接入说明
```

公共领域和业务服务不得依赖 UI；Qt Widgets 页面不得直接操作 SQLite、钱包或权限规则。

## 12. 建议研发流程

研发采用“先一致性基础、再端到端主流程、最后扩展与验收”的顺序。每个阶段只有达到退出条件后才进入下一阶段。

| 阶段 | 主要工作 | 关键交付物 | 退出条件 |
| --- | --- | --- | --- |
| 1. 工程基础 | 建立用户端、管理端、公共库和测试目标；统一配置、日志、错误和 CMake | 可构建的工程骨架、CI/本地构建脚本、烟雾测试 | Ubuntu 构建通过，两个空壳程序可启动，测试框架可运行 |
| 2. SQLite 与领域核心 | 实现 schema、迁移、种子、仓储、状态机、钱包、价格和事务 | 公共数据层、90 天种子、领域/数据库测试 | 首次启动可建库，双进程 WAL 可用，分配与结算并发测试通过 |
| 3. Socket 与服务器运行时 | 实现协议编解码、认证会话、重连、设备模拟、调度和持续计费 | 管理端 Socket 服务、协议文档、虚拟客户端 | 拆包/粘包/重连/幂等测试通过，断线计费可恢复 |
| 4. 用户端主流程 | 实现登录、站点、详情、排队、预约、充电、结算、钱包和订单 | 可完整演示的 420×760 用户端 | `UC-U-01`～`UC-U-10` 正常流和异常流通过 |

### 12.1 每项功能的实施循环

1. 从 SRS 选择一个用例或非功能需求，记录对应编号和验收标准。
2. 明确输入、输出、权限、状态变化、失败路径和数据事务边界。
3. 先补充领域或接口测试，再实现公共服务与基础设施。
4. 接入 UI 或 Socket，补充集成测试和可观察错误提示。
5. 执行构建、相关测试、烟雾测试和 `git diff --check`。
6. 更新需求追踪和必要文档，通过代码审查后合并。

### 12.2 团队协作建议

- 一个 Pull Request 聚焦一个可验证目标，并关联 `UC-*`、`BR-*` 或 `NFR-*`。
- 优先按纵向功能切片协作，避免多人同时修改同一大文件。
- 数据库迁移、Socket 协议、公共状态码和领域接口变更必须先评审，再并行开发调用方。
- 生成文件、构建目录、真实 `.env`、数据库、日志、备份和密钥不得提交。
- 合并前至少由另一名成员检查需求覆盖、线程边界、事务一致性和测试证据。

## 13. 完成定义

一项需求只有同时满足以下条件才可标记完成：

- 实现可追踪到明确的 SRS 编号。
- 正常流、异常流、权限和边界条件均有验证证据。
- UI 不含 SQL 或核心业务规则，后台工作不阻塞事件循环。
- 数据库事务、幂等和失败恢复符合本指南。
- 相关单元、集成或端到端测试通过。
- Ubuntu 目标构建通过，界面无静默失败。
- 文档、配置示例和需求追踪已同步更新。

整个项目只有在 SRS 全部适用条目、性能指标和 12 项验收清单均有通过证据后，才可标记为完成。
