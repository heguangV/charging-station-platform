# 单一目标的需求决策与未确定问题

## 1. 已统一的最终方向

当前验收目标统一为固定 420×760 的 Linux Qt Widgets 用户端、同时承载 `QTcpServer` 的 Linux Qt Widgets PC 管理端、双进程共享 SQLite、Web 大屏和 Python ML。Android/QML 与 PostgreSQL 云架构转为远期路线，不作为当前版本完成条件。

SRS 的功能、异常流和可观测结果保留；技术替换必须能够显著改善移动端支持、并发、云部署或安全性。

SRS 是不可降低的最低交付基线。本文档中的历史决定、用户后续表述或未确定问题若删减、弱化或推迟 SRS 已要求的能力，该部分决定自动失效并恢复 SRS 表述；只有增加能力、提高指标或经验证完整等价的技术替换可以覆盖实施细节。

## 2. 已确定的等价增强

| 事项 | 单一目标决定 |
| --- | --- |
| 用户端 UI | Qt Widgets 桌面 GUI，验收窗口固定 420×760 |
| 管理端 UI | Linux Qt Widgets + Qt Charts，并承载 `QTcpServer` |
| 数据访问 | `ncs_user` 与 `ncs_admin` 通过公共数据层访问同一 SQLite；Socket 传递实时消息和运维命令 |

| 时间 | SQLite 保存 UTC ISO 8601 文本，客户端显示本地时间 |
| 密码 | 使用专用密码哈希，不使用单次加盐 SHA-256 |

| ML | 按 SRS 使用 RandomForest、规定特征与三种评估指标 |

## 3. 已合并的产品规则

- SRS 的直接预约与既有即时排队同时存在：有空闲桩直接预约 15 分钟；无空闲桩加入队列，轮到后 5 分钟确认，再进入 15 分钟预约。
- 即时队列按“站点 + 快充/慢充类型”建立；用户不指定具体设备，同类型任一兼容设备释放后按入队顺序分配。
- 保留用户名/手机号 + 密码作为正式登录；开发环境额外提供 SRS 模拟验证码自动注册演示。
- 恢复 SRS 的昵称、头像和手机号必填要求；新用户初始余额按 SRS 设置为 0。
- 每个价格区域分别保存电费和服务费，总价等价于 SRS 的站点单价；北京种子数据按区域设置可区分的基础价格。
- 价格管理改为分区基础定价，不提供全市一键同步；排队压力可以影响价格，ML 提供未来价格浮动趋势建议。
- 正常充电达到余额上限自动停止；发生不可避免的计费超额时记录欠费，兼容 SRS 兜底。
- 北京固定 5 个站点和 48 台设备，保留 6 台故障设备并生成 90 天历史数据；管理端和大屏默认展示近 30 天。
- 保留说明书的车主用户、运营管理员和决策查看者三类角色；运营管理员可管理并查看大屏，决策查看者只能读取大屏数据。
- 大屏和 ML 属于当前目标；Android/QML、TPNS、PostgreSQL 与公网云部署记录为远期路线。

## 4. P0：需要用户确认的核心规则

### Q1 排队建立范围（已确认）

- 按 `站点 + 快充/慢充类型` 建立即时队列。
- 用户不指定具体设备，公共业务服务层在 SQLite 事务中分配该类型最先可用的兼容设备。
- 同一队列按服务端入队时间排序；同一时刻使用数据库生成的顺序号稳定排序。

### Q2 价格管理范围（已确认）

已确认：

- 北京采用分区基础定价，不提供全市一键同步功能。
- 当前版本按北京行政区划分价格区域，站点使用腾讯地图返回的 `adcode` 归区；数据库使用独立 `pricing_zone` 和站点 `zone_id`，保留未来自定义区域能力。
- 当前排队人数可以影响价格。
- 机器学习根据历史负荷、时段和预测排队压力给出未来价格浮动趋势建议。
- 排队人数使用确定性阶梯规则自动调整服务费，不自动改变电费。
- ML 只输出未来 1/6/24 小时的趋势、建议幅度和原因，须由运营管理员确认后生效，不能直接自动调价。
- 每次自动调价或管理员采纳建议都记录原价、新价、原因、操作者和生效时间。
- 排队压力定义为“等待人数 ÷ 当前可运营的同类型设备数”，故障、停用和重启中设备不计入分母。
- 阶梯为：压力 `≤0.5` 不调整、`(0.5,1]` 服务费上浮 10%、`(1,2]` 上浮 20%、`>2` 上浮 30%；每 5 分钟计算一次，压力下降时自动回落但不低于区域基础服务费。
- 任何价格变化不追溯修改历史订单；活动流程使用价格快照。
- 直接预约在预约成功事务中保存价格快照；加入队列时只展示当前预估价和最高浮动范围。
- 轮到排队用户时生成 5 分钟有效的最终报价，列明电费、基础服务费、排队浮动和总单价；确认后以该报价创建 15 分钟预约，拒绝或超时不收费并递补下一位。
- ML 建议调整范围为 `-20%～+20%`、步长 5%，管理员确认时选择 1/6/24 小时有效期，到期自动失效。
- 最终服务费按 `区域基础服务费 × (1 + 已批准 ML 调整比例 + 排队调整比例)` 计算，统一限制在基础服务费的 80%～140%，并按分/度四舍五入保存。

固定基础价格为：

| 行政区 | 电费（分/度） | 服务费（分/度） | 基础总价（元/度） |
| --- | ---: | ---: | ---: |
| 海淀区 | 85 | 50 | 1.35 |
| 朝阳区 | 90 | 55 | 1.45 |
| 丰台区 | 80 | 45 | 1.25 |
| 石景山区 | 75 | 40 | 1.15 |
| 通州区 | 70 | 35 | 1.05 |

全市统一最低起充金额为 500 分。

### Q3 欠费后的账号行为（已确认）

- 正常情况下按余额上限自动停止；极小计费超额记录欠费。
- 欠费用户仍可登录、查看订单、查看欠费明细和充值，但禁止加入队列、创建预约或开始新充电。
- 充值事务先清偿欠费，剩余金额再进入虚拟余额；清偿与余额入账分别生成不可变钱包流水。
- 充值不足时余额保持 0 并减少剩余欠费；欠费清零且账号未冻结或注销时，自动恢复新充电权限。

### Q4 使用中设备远程重启（已按说明书基线修订）

- 空闲或故障设备经二次确认后可以立即模拟重启，重启状态持续 2 秒。
- 待确认、已预约或尚未释放的待结算设备优先登记“释放后自动重启”；确需立即处理时先完成对应的受控释放流程。
- 为保留说明书要求，充电中设备允许运营管理员执行紧急远程重启，但必须二次确认并填写原因；管理端先在 SQLite 事务中停止计费，按已产生电量幂等结算或生成待处理结算，通过 Socket 通知用户并完整审计，再执行模拟重启。失败时不得直接释放设备或丢失订单数据。
- 重启命令记录管理员、原因、创建/执行时间和结果；重启中设备不可分配。

### Q5 数据大屏登录（已按说明书基线修订）

- 保留独立决策查看者角色，避免把说明书规定的三类角色缩减为两类。
- 状态正常的运营管理员和决策查看者均可访问本地大屏；决策查看者只能读取 Dashboard 数据，不能执行任何修改。
- 大屏不开放自行注册；角色权限由 PC 服务器端校验，不能只依靠前端隐藏页面。

## 7. P3：SQLite、Socket 与安全设计

- 主数据库使用 SQLite 3 单文件 `charge_platform.db`；`ncs_user` 与 `ncs_admin` 通过公共数据/服务层在同机访问同一文件，大屏不得直接写数据库。
- 任一 Qt 程序首次启动时在进程间初始化锁保护下自动建表和播种，后续由 `schema_version` 管理版本；已执行迁移不得修改，结构迁移、必要参考数据和可重建演示种子分离。
- 主键优先使用 `INTEGER PRIMARY KEY`，金额/单价使用分为单位的 `INTEGER`，电量使用毫瓦时 `INTEGER`，时间使用 UTC ISO 8601 `TEXT`，状态使用 `INTEGER + CHECK`，经纬度使用 `REAL`。
- 每个进程使用专用数据库工作线程和独立连接，启用 `foreign_keys`、WAL 和 `busy_timeout`；分配与结算使用 `BEGIN IMMEDIATE`、条件更新、唯一索引、事务和幂等键保证一致性，冲突最多重试 3 次。
- Socket 协议采用“4 字节网络序长度 + UTF-8 JSON”，消息包含版本、请求 ID、类型、时间和数据；设置最大帧长度并处理拆包、粘包、超时、异常断线和重连快照。
- 使用管理端生成的随机不透明会话令牌：普通用户最长 30 天、最多 3 个桌面终端；管理员最多 2 个终端，超限撤销最早会话，退出和注销立即撤销。
- 头像保存于 `QStandardPaths` 确定的 `avatars/` 目录，客户端校验真实格式、大小与尺寸并重新编码去除元数据，每周清理孤立文件。
- 应用日志统一写入 `logs/ncs_YYYYMMDD.log` 并保留 30 天，审计/运维日志保留 180 天；管理端通过在线备份或 `VACUUM INTO` 生成一致性快照，每日保留 7 份、每周保留 4 份并可加密同步云服务器。RPO 为 24 小时、RTO 为 4 小时。
- 腾讯地图 WebService Key 只由 PC 服务器端读取，JS Key 限制本地地图页来源，开发/演示 Key 分离；密钥不进入 Git。
- 当前桌面版使用 Socket 站内通知，不接入 TPNS；Android 系统推送随远期移动端路线再设计。
- 团队通过 Git 共享 schema、迁移和种子脚本，各自使用本地 SQLite 文件；严格验收时两个 Qt 程序与数据库位于同一 VM，不通过网络目录共享数据库。

## 8. P4：大屏与机器学习细节

### 大屏

- 管理端或 Python 脚本每 30 秒从 SQLite 聚合并原子替换 `web/public/data/dashboard.json`，大屏按相同周期拉取。
- 快照包含 `schema_version`、`generated_at`、指标、图表和预测。集合无数据返回空数组，确实无法计算的值才返回 `null` 并说明原因；生成失败保留最近成功文件并显示过期状态。
- 营收只统计结算成功订单，业务日/月按 `Asia/Shanghai` 划分，SQLite 保存 UTC；在线设备为最近 60 秒有心跳或正在模拟运行的设备，注册用户不含已注销用户，页面显示数据截止时间。
- 管理员 Web 会话最长 8 小时、空闲 30 分钟退出；敏感操作超过 15 分钟未重新验证密码时要求复验。

### 机器学习

- 历史种子固定生成 90 天以支持 168 小时滞后和时间切分，ML 使用完整数据，界面默认展示近 30 天。
- 天气按随机种子 `20260901` 生成可重复的天气与温度，节假日来自仓库内版本化日历；数值缺失用训练集的中位数、分类缺失记 `UNKNOWN`，最初不足 168 小时滞后的样本不进入训练。
- MAPE 仅对真实值大于 0 的样本计算并报告排除数量；MAE/RMSE 始终计算，额外提供 WAPE 辅助解释零负荷时段。
- 模型必须在固定测试集上优于朴素基线才能通过说明书规定的 ML 验收。未优于时标记为不合格、暂停生成 ML 调价建议并暂用朴素基线保持页面可用，但 ML 子系统和完整产品不得标记为验收完成。
- 预测繁忙数为“预测充电量 ÷ 最近 30 天单台繁忙设备小时均量”向上取整并限制到可运营设备数；空闲数为两者之差。预测占用率达到 80% 或负荷达到该站历史 90 分位数时标记高峰。
- 同时最多一个训练任务和一个预测任务，超时分别为 10 分钟和 2 分钟；重复请求返回当前任务。模型缺失时用朴素基线，失败保留最近成功结果并标记过期；模型保留 30 天，预测和评估历史保留 90 天。

## 9. P5：部署、界面与交付信息
