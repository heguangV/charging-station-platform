# 基础说明书差异与未完成需求分析

## 1. 用途

本文件把项目基础说明书与此前问答决定进行对照，帮助团队在编码前冻结验收范围。基础说明书优先；存在冲突时，应先取得课程负责人或项目负责人的明确确认。

## 2. 已完成的整合修正

| 事项 | 原有项目文档 | 基础说明书 | 整合结果 |
| --- | --- | --- | --- |
| 用户端平台 | 仅 Android | Linux + Qt 手机式界面 | 共享 QML 同时支持 Linux/Android，Android 优先开发 |
| 导航 | 第一版不做 | 腾讯地图驾车/步行导航 | 恢复为基础必做 |
| 设备状态 | 只做空闲/充电中 | 在用/闲置/故障 | 恢复基础故障状态 |
| 远程重启 | 不做异常操作 | 管理员模拟远程重启 | 恢复为基础必做 |
| Web 大屏 | 未纳入主线 | Web + ECharts 核心子系统 | 纳入最终交付路线 |
| 机器学习 | 未纳入主线 | 1/6/24 小时负荷等预测 | 纳入最终交付路线，最低范围待确认 |
| 未完成订单 | 未明确前置拦截 | 新充电前必须检查并跳转结算 | 纳入核心流程 |
| 管理统计 | 近 7 日趋势 | 近 7/30 日、今日/月/总营收 | 补齐基础指标 |

## 3. P0：编码前必须确认的冲突

### Q1 用户端最终平台

- 基础说明书：Linux + Qt，桌面窗口模拟手机交互。
- 已确认扩展：先开发 Android。
- 推荐默认：Qt Quick/QML + C++ 共享代码，同时生成 Linux 和 Android 目标；Android 先做，但不能删除 Linux 验收目标。
- 需要确认：课程验收是否允许只展示 Android。

### Q2 地图服务商

- 基础说明书：腾讯地图 Web API，并要求地址解析和驾车/步行导航。
- 当前准备：已申请高德地图 Key，原方案使用高德。
- 推荐默认：为满足文字验收，切换腾讯地图；仅在负责人明确允许等价替换时继续使用高德。
- 需要收集：腾讯地图 Key、允许的 Web 域名/来源限制、调用配额和课程替换意见。

### Q3 数据库技术

- 基础说明书正文：SQLite。
- 基础结构图：MySQL、InfluxDB、MinIO。
- 当前决定：PostgreSQL。
- 推荐默认：PostgreSQL 作为统一主库，第一版不额外部署 MySQL/InfluxDB/MinIO；通过表结构覆盖业务与时序演示数据。
- 需要确认：课程是否按技术名称验收，还是只检查数据库设计与功能。

### Q4 登录与用户资料

- 基础说明书：11 位手机号免密登录，不存在即注册；默认昵称、头像，可修改昵称和头像。
- 当前决定：用户名或手机号 + 密码，手机号选填，不需要昵称。
- 风险：公网免密手机号登录可直接冒用他人账号。
- 推荐默认：保留安全的密码登录作为公网方案；若必须复刻基础流程，只在隔离演示配置中提供测试手机号免密登录。昵称和头像是否恢复需明确决定。
- 需要确认：验收是否要求逐项展示免密、自动注册、昵称和头像修改。

### Q5 管理员默认账号

- 基础说明书：`admin / 123456`。
- 安全要求：公开默认密码不能部署到云服务器。
- 推荐默认：本地演示数据库可生成该账号并强制首次改密；云端必须使用初始化命令设置独立密码。
- 需要确认：演示时是否必须使用指定默认账号。

### Q6 Socket 与多线程验收形式

- 基础说明书：掌握 Socket 通信、pthread 多线程，主框架为多线程结构。
- 当前方案：Qt HTTP Server、Qt WebSocket 和 Qt 异步/线程机制。
- 推荐默认：业务使用 Qt 网络与线程封装；另提供可测试的线程池/后台任务和通信协议设计。
- 需要确认：是否必须直接出现 `pthread_*`、POSIX Socket 或 `QTcpSocket` 代码。

### Q7 机器学习最低交付范围

- 基础要求：1/6/24 小时负荷、空闲桩、高峰时段预测，并用于推荐和预警。
- 当前缺口：没有真实历史数据、算法和评价标准。
- 推荐默认：生成可复现的模拟时序数据；先做一种基线回归/时序模型，输出三个预测时间窗，并在用户端和管理端各展示一个结果。
- 需要确认：是否必须训练真正模型，还是规则/统计预测可以验收；是否允许 Python 实现 ML 服务。

## 4. P1：核心业务规则未完成

1. 即时排队按整个站点、快慢充类型还是指定设备建立队列？
2. 用户何时可以取消排队；取消后是否立即递补下一位？
3. 5 分钟确认期内设备状态如何显示，是否允许管理员释放？
4. 电费单价和服务费单价分别是多少？说明书示例只展示总充电价格。
5. 三个北京站点的名称、地址和经纬度是什么？
6. 每站 4 个设备如何分配快充/慢充，功率分别是多少？
7. 状态机如何覆盖闲置、已分配、充电中、故障、重启中和停用？
8. 远程重启是只允许故障设备，还是闲置设备也允许？重启持续多久、成功率是否固定？
9. 未完成订单包括“充电中”和“待结算”中的哪些状态？如何补结算？
10. 订单取消、启动失败、结算失败和余额返还如何转换状态？
11. 自定义充值上下限、钱包余额上限和管理员调整上限是什么？
12. 新用户赠送 100 元是否同时适用于说明书的手机号自动注册流程？

## 5. P2：Web 大屏与机器学习信息缺口

### Web 大屏

需要确认：

- 最低展示页面数量，是单页综合大屏还是多页面分析系统。
- 必须包含的指标及计算口径。
- 数据刷新频率和是否需要 WebSocket 实时更新。
- 是否需要登录、运营人员和决策者是否使用不同权限。
- 是否需要地图分布、站点评价和设备健康度。

### 机器学习

需要收集：

- 模拟数据覆盖多少天、多少站点、何种采样粒度。
- 天气数据来自真实 API、固定样本还是随机生成。
- 节假日数据来源。
- 输入特征、目标变量和缺失值处理规则。
- 训练/测试切分方式以及 MAE、RMSE 等最低评价指标。
- 模型多久训练一次、预测多久刷新一次、模型文件如何保存。
- 无模型或预测失败时的降级行为。
