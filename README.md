# 电动汽车充电桩应用管理平台

## 1. 文档定位与需求优先级

本仓库用于完成“东软电动汽车充电桩应用管理平台”教学项目，覆盖需求理解、系统设计、详细设计、开发、测试和发布全过程。

需求按以下优先级管理：

1. 《01.项目说明书-东软电动汽车充电桩应用管理平台》是最终验收的基础要求。
2. 后续问答中确认的决定用于细化、扩展或改进基础要求。
3. 如果后续决定与基础说明书冲突，先在 [需求差异与待确认清单](docs/requirements-gap-analysis.md) 中记录；未获得课程负责人认可前，不把基础验收项删除。
4. 安全要求不会因为演示账号、模拟登录或公开仓库而降低；本地演示配置与公网部署配置必须隔离。

本文使用以下状态：

- **基础必做**：说明书明确要求，最终项目必须覆盖。
- **已确认扩展**：用户已经确认、且不替代基础要求的增强功能。
- **待确认替换**：与说明书指定平台或技术不同，需要确认是否允许替换。
- **后续能力**：不属于当前教学项目最低验收范围。

## 4. 充电用户端

### 4.1 平台策略

- 基础验收需要 Linux 桌面环境中的 Qt 手机式用户端。
- 已确认优先开发 Android，包名为 `io.github.heguangv.chargingstation`。
- 推荐使用 Qt Quick/QML + C++ 建立一套共享界面和业务客户端，同时构建 Linux 与 Android 两个目标，避免维护两套逻辑。
- 最终是否允许只交 Android 而不交 Linux 用户端，必须取得课程负责人确认。

### 4.2 附近充电站查询（基础必做）

- 支持下拉选择区域和手动输入地址，模拟 GPS 定位。
- 将地址转换为经纬度，并按距离从近到远展示站点。
- 站点卡片显示站名、充电价格、电桩总数、空闲数和距离。
- 站点详情显示电桩编号、快充/慢充类型、状态和功率。
- 当前项目限定北京市，暂定朝阳、海淀、丰台三个模拟站点，每站 4 个充电桩。
- 说明书指定腾讯地图 Web API；此前已申请高德地图 Key。地图服务替换属于待确认差异，默认以腾讯地图满足验收。

### 4.3 导航（基础必做）

- 用户点击距离或导航按钮后进入地图路线规划页面。
- 使用模拟当前位置作为起点、目标站点作为终点。
- 至少提供驾车和步行两种方式。
- 通过 Qt WebEngine/WebView 加载地图 Web 页面。

### 4.4 用户登录与资料（存在冲突，必须先确认）

说明书要求输入 11 位手机号免密登录：已存在则直接登录，不存在则自动注册，并生成默认昵称和头像；用户可修改头像、昵称并查看钱包。

此前问答选择了“用户名或手机号 + 密码”、手机号选填、不使用昵称。两种方案不可同时作为唯一主流程，具体处理见第 11 节。公网服务不得直接开放仅凭手机号即可登录他人账号的接口。

已确认的补充规则：

- 仅绑定手机号的用户可以使用密码重置。
- 第一版使用明确标注的模拟验证码，不接真实短信平台。
- 注销时删除登录凭据与手机号，订单和资金流水匿名保留。

### 4.5 钱包与模拟充值

- 展示虚拟钱包余额并支持输入金额模拟充值，不接真实支付。
- 当前补充方案为新用户赠送 100 元，可快捷充值 50/100/200 元或自定义金额。
- 所有余额变化形成不可变流水；管理员调整余额必须填写原因并记录审计日志。
- 页面明确标注“虚拟余额”，不提现、不代表真实资金。

### 4.6 充电、计费与结算

- 进入充电流程前，查询用户是否存在充电中或未结算订单。
- 存在未完成订单时阻止新充电，并跳转到订单处理或结算页面。
- 用户选择空闲电桩，经过“排队/分配—开始充电—计费—结束—结算”形成完整订单。
- 页面持续显示时长、充电量、电费、服务费和总额。
- 用户可以手动结束，也可在达到目标金额或余额上限时自动结束。
- 全北京市第一版采用统一电费和服务费；具体单价待确认。
- 结算、余额扣减和流水写入必须在同一事务中完成并支持幂等。

### 4.7 即时排队与通知（已确认扩展）

- 第一版只支持设备繁忙后的即时排队，不支持未来日期或时间段预约。
- 后端维护排队顺序、设备分配和状态，客户端不能自行决定顺序。
- 轮到用户后保留设备 5 分钟；超时未确认则释放设备并继续队列。
- 在线使用 WebSocket 提醒，后台或离线使用腾讯云 TPNS 基础推送。
- 点击通知后必须重新查询后端，推送不是业务事实来源。
- 第一版不接华为、小米、OPPO、vivo 等厂商专用通道。

## 5. PC 服务器管理端（Linux + Qt）

### 5.1 管理员登录

- 使用账号和密码登录，角色权限由后端验证。
- 说明书给出开发演示初始账号 `admin / 123456`；该凭据只能用于隔离的本地演示，并强制首次修改。
- 公网环境通过初始化命令创建管理员，禁止保留公开默认密码。
- 当前扩展为普通用户、运营人员、系统管理员三个角色。

### 5.2 销售业绩（基础必做）

- 使用 Qt Charts 折线图展示近 7 日和近 30 日营收趋势。
- 展示今日营收、本月营收和总营收。
- 支持切换时间维度，统计口径使用已结算虚拟订单。

### 5.3 电桩状态与管理（基础必做）

- 汇总在用、闲置、故障三种状态的数量和占比。
- 列表展示编号、所属站点、快充/慢充、功率、状态、累计充电次数和累计充电时长。
- 支持模拟“远程重启”故障电桩，并记录命令、结果和操作日志。
- 基础故障状态与远程重启必须恢复到项目范围；更复杂的离线、维护、升级和故障诊断仍可后置。

### 5.4 充电站管理（基础必做）

- 展示站点 ID、站名、地址、经纬度、电桩总数和在线率。
- 查看站内全部电桩实时状态。
- 支持新增站点，填写站名、地址、经纬度和电桩数量。
- 是否允许编辑、停用和删除站点仍需确认；有历史订单的站点不得直接物理删除。

### 5.5 用户与订单管理（基础必做）

- 用户列表至少包含 ID、手机号、昵称/显示名、钱包余额、注册时间和正常/冻结状态。
- 支持按手机号模糊搜索，支持冻结和解冻。
- 订单支持按编号、用户、站点、设备、状态和时间查询。
- 扩展显示余额流水、计费快照和管理员审计日志。

## 6. 大数据可视化大屏（Web + ECharts）

最终项目至少应具备：

- 实时运营监控与综合决策看板。
- 营收趋势和核心金额指标。
- 充电站、充电桩状态与在线率分析。
- 充电负荷、订单量和用户行为的基础统计。
- 从平台服务层获取聚合数据，禁止浏览器直接连接数据库。

界面图片只是参考，不要求复刻布局和视觉风格。最低页面、刷新频率、指标口径和访问权限仍需确认。

## 7. 机器学习智能分析子系统

说明书要求利用历史充电时段、时长、充电量、用户出行时段、天气和节假日等数据，对未来 1 小时、6 小时和 24 小时进行预测，输出：

- 各站点充电负荷预测。
- 空闲充电桩数量预测。
- 高峰充电时段预测。
- 用户端低拥堵站点推荐。
- 管理端负荷预警和调度参考。

当前没有真实设备和历史数据，因此需要确定演示数据生成方式、最低算法、训练/推理语言、评价指标和展示方式。在这些问题确认前，不宣称已具备“精准预测”能力。

设备故障诊断、需求调度优化和智能风控出现在总体能力描述中，但详细功能只明确了负荷预测；暂列为加分扩展，不作为第一轮实现目标。

## 8. 平台业务服务、通信与并发

- 后端使用 C++17 + Qt，提供用户、站点、充电桩、排队、订单、计费、钱包、设备控制和统计服务。
- 客户端通过版本化 HTTPS API 和 WebSocket 访问后端，不直接访问数据库。
- WebSocket 用于充电进度、设备状态、队列变化和管理看板实时数据。
- 说明书明确要求 Socket 编程和多线程；是否必须展示原生 `pthread`/TCP Socket API，还是允许使用 Qt 的线程与 Socket 封装，列为验收确认项。
- 网络、数据库、预测任务和文件处理不能阻塞 UI 线程；必须明确线程所有权、任务取消、超时和关闭流程。
- 通信数据具有版本、类型、请求 ID、时间、载荷和错误信息，处理断包、重复请求、超时、重连和非法数据。
- 后端是设备、队列、订单、计费和余额的唯一可信来源。

## 9. 数据库与数据对象

说明书要求完成数据库设计、开发与管理，但技术名称内部不一致：正文写 SQLite，结构图写 MySQL、InfluxDB 和 MinIO；此前问答已选择 PostgreSQL。因此 PostgreSQL 作为当前推荐主库，但是否允许替换仍需确认。

核心数据对象：

| 分类 | 数据对象 |
| --- | --- |
| 账号 | 用户、管理员、角色、登录会话、验证码、推送设备令牌 |
| 站点设备 | 充电站、充电桩、状态变化、设备命令与操作日志 |
| 充电业务 | 排队、设备分配、充电会话、订单、计费明细 |
| 资金 | 虚拟钱包、充值记录、余额流水、管理员调整记录 |
| 运营 | 营收聚合、服务器指标、系统配置、审计日志 |
| 智能分析 | 天气/节假日、充电时序样本、特征、模型版本、预测结果 |
| 文件 | 用户头像、站点图片、日志或模型文件；具体存储方式待确认 |

数据设计要求：

- 使用主键、外键、唯一、非空、检查约束、索引和明确删除策略。
- 结构变化通过版本化迁移执行，空库可迁移到当前版本。
- 使用参数化查询，密码、令牌和验证码只保存安全摘要。
- 金额以分为单位，充电量使用明确精度的定点值。
- 订单、会话和钱包流水不物理删除；账号注销后匿名保留业务凭证。
- 开发、测试与云端数据库和凭据相互隔离。

## 10. 安全、错误处理、日志与备份

- 建立统一错误码、用户可理解提示和服务端诊断上下文。
- 覆盖输入错误、无权限、余额不足、状态冲突、数据库失败、网络超时、地图失败、推送失败和预测不可用。
- 认证、角色权限、业务校验、事务和审计均在后端执行。
- 公网通过 Nginx 和 TLS，仅开放必要端口；数据库不直接暴露公网。
- 地图、TPNS、数据库和云服务密钥只放在环境配置中，不进入 Git、APK 或日志。
- 运行日志、管理员审计、设备命令和备份结果分开管理。
- PostgreSQL 候选方案下，每日备份保留 7 份、每周备份保留 4 份，并至少验证一次恢复。
- 具体错误码表、日志保留期、备份目标和故障恢复指标仍需形成详细设计。

## 12. 推荐实施阶段

1. **需求冻结**：解决第 11 节的验收冲突，明确地图、数据库、登录资料、Socket/线程和机器学习最低范围。

5. **扩展体验**：Android、地图定位与导航、即时排队、WebSocket、TPNS。
6. **数据展示与智能分析**：ECharts 大屏、演示数据集、1/6/24 小时预测、推荐和预警。
7. **交付验证**：并发、Socket、错误处理、安全、备份恢复、文档、演示脚本和发布。
