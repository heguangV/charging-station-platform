# 电动汽车充电桩应用管理平台 NCS

## 1. 需求依据

本仓库用于完成充电桩应用管理平台教学项目。需求来源按以下顺序解释：

1. [软件需求规格说明书（SRS）](docs/01-requirements-specification.md) 是当前最详细的文字需求，也是功能、异常流、非功能指标和验收项的主要依据。
2. 原始《项目要求书》用于补充项目目标、开发体制和总体背景；其中参考界面只作为视觉参考。
3. 后续问答决定作为扩展需求；与 SRS 冲突时，不直接覆盖基线，而是记录在 [需求差异、扩展与未确定问题](docs/requirements-gap-analysis.md) 中。

实现某个功能时，必须回查其 `UC-*`、`BR-*` 和 `NFR-*` 原文，不能只依赖 README 摘要。

## 2. 两条交付路线

### 2.1 A 线：教学验收基线

这是 SRS 明确描述的版本，应优先形成可独立演示的闭环：

| 项目 | 基线要求 |
| --- | --- |
| 用户端 | `ncs_user`，Qt Widgets 手机竖屏桌面程序，420×760 |
| 管理端 | `ncs_admin`，Qt Widgets + Qt Charts，最小 1280×800 |
| 数据库 | SQLite 3 单文件 `charge_platform.db`，两个程序访问同一文件 |
| Web 大屏 | Vue 3 + ECharts，1920×1080 单页深色看板 |
| 机器学习 | Python 3.10 + scikit-learn RandomForestRegressor |
| 开发/验收 | Windows 10/11 可开发，Ubuntu 22.04 为交付验收环境 |
| 基础技术 | Qt 6.5.3、C++17、CMake；当前 Qt 6.8.3 满足版本下限 |

A 线是单机教学系统，没有独立网络后端。腾讯地图属于可选外部依赖；没有 Key 或网络时必须能够降级运行。

### 2.2 B 线：网络与移动端扩展

此前已经确认的 Android、云端和团队研发方案保留为扩展路线：

- Android Qt Quick/QML 用户端，包名 `io.github.heguangv.chargingstation`。
- C++/Qt REST + WebSocket 后端，部署到 Ubuntu Server 24.04。
- PostgreSQL、Nginx、TLS、备份、审计和环境化密钥。
- 即时排队、WebSocket 在线提醒和腾讯云 TPNS 系统推送。
- 用户名/手机号 + 密码、三角色权限、模拟密码重置。
- 虚拟余额、目标金额自动结束、电费与服务费拆分。

B 线不能改变 A 线验收行为。推荐共享领域模型和服务接口，为 SQLite 本地实现与 PostgreSQL 网络实现提供不同适配器。

是否采用这种“双路线、共享核心”的交付策略，是当前最高优先级待确认问题。

## 3. 用户角色

SRS 基线定义三个角色：

| 角色 | 入口 | 权限 |
| --- | --- | --- |
| 车主用户 | `ncs_user` | 登录、查站、导航、资料、充值、预约、充电、结算、订单 |
| 运营管理员 | `ncs_admin` | 营收、设备、站点、用户、订单和预测管理 |
| 决策者 | 浏览器大屏 | 只读查看运营与预测数据 |

B 线将运营管理员进一步拆分为运营人员和系统管理员；该拆分不影响 A 线页面验收。

## 4. 全局业务规则

以下规则直接来自 SRS，除非差异清单明确批准变更：

| 编号 | 基线规则 |
| --- | --- |
| BR-01 | 手机号是用户唯一标识，必须为以 1 开头的 11 位数字 |
| BR-02 | 一个用户同一时刻最多有一个预约或充电中的未结算订单 |
| BR-03 | 一个电桩同一时刻最多只能被一个订单占用 |
| BR-04 | 余额必须大于最低起充金额，默认 5 元 |
| BR-05 | 费用 = 累计电量 × 电站单价，显示保留两位小数 |
| BR-06 | 结算余额不足时扣至 0，并记录欠费金额 |
| BR-07 | 冻结用户不能登录或开始新充电 |
| BR-08 | 故障电桩不能预约或开始充电 |
| BR-09 | 基线金额单位为元、电量单位为 kWh、时间保存为本地时间字符串 |
| BR-10 | 电站下仍有电桩时禁止删除电站 |

并发预约、结算和批量创建电桩必须使用数据库事务。跨平台扩展可以采用整数分和带时区时间，但必须保证 A 线界面、数据迁移与验收口径一致。

## 5. 充电用户端需求

### 5.1 登录与自动注册（UC-U-01）

- 输入手机号，点击获取验证码后生成 6 位模拟码，按钮倒计时 60 秒。
- 验证码直接显示在界面提示区；输入正确后按手机号登录。
- 新手机号自动创建用户：默认昵称为“用户 + 手机号后 4 位”、默认灰色头像、余额 0、状态正常。
- 冻结用户拒绝登录；数据库失败、非法手机号、未获取验证码和验证码错误均有明确提示。
- 同一手机号再次登录不得重复创建用户，并保留资料与余额。

### 5.2 附近站点与详情（UC-U-02～03）

- 提供区域下拉框、地址输入和定位按钮；无 GPS 时使用软件模拟位置。
- 配置腾讯地图 Key 且联网时使用地理编码；失败时回退预置坐标。
- 使用 Haversine 公式计算直线距离并升序排列。
- 卡片显示站名、单价、空闲数/总数、距离；空闲数实时按 `charger.status=0` 聚合。
- 详情显示地址、单价、距离和电桩编号、快慢充类型、功率、状态、累计充电次数。
- 空数据、地址失败和网络超时不能导致崩溃或空白假死。

### 5.3 一键导航（UC-U-04）

- 支持驾车、步行和公交三种方式。
- 首选 `QWebEngineView` 加载本地 HTML 与腾讯地图 JS API。
- 无 WebEngine、Key 或网络时，显示坐标和直线距离，并允许系统浏览器打开腾讯地图路线链接。
- 验收需要能够提供路线规划画面截图。

### 5.4 用户中心（UC-U-05）

- 展示圆形头像、昵称、脱敏手机号、余额和注册时间。
- 头像支持 PNG/JPG/JPEG/BMP，最大 5MB，复制到应用数据目录并保存相对路径。
- 昵称长度 1～20，禁止纯空白。
- 模拟充值范围 0.01～10000 元、最多两位小数，成功后立即持久化。
- 充值流水在 SRS 中标为可选；B 线要求其成为必做审计数据。
- 退出登录返回登录窗口并清理当前会话。

### 5.5 未结算订单拦截（UC-U-06）

- 进入充电入口前查询 `status IN (0,1)` 的订单。
- 存在时只允许“去结算”，不得进入新选桩流程。
- 如何同时满足“充电中订单恢复继续计费”需要进一步明确，见差异清单。

### 5.6 预约、充电与结算（UC-U-07～09）

- 只展示空闲电桩；预约前检查最低起充金额。
- 事务内占用电桩并创建 `status=0` 的预约订单。
- 预约保留 15 分钟；超时取消订单并释放电桩。
- 点击开始后订单变为 `status=1`，记录开始时间并启动计费。
- 每秒展示时长、电量、费用、实时功率和模拟 SoC。
- 默认时间倍率 60；进程退出后可根据开始时间恢复计费。
- 结束时在同一事务中完成订单、设备统计和余额扣减，失败整体回滚。
- 结算小票包含订单、站点、设备、起止时间、时长、电量、单价、金额和余额。

### 5.7 我的订单（UC-U-10）

- 按时间倒序展示当前用户订单。
- 显示站点、设备、时间、电量、金额和状态，并可查看结算小票。

## 6. PC 管理端需求

### 6.1 登录和框架（UC-A-01～02）

- 默认本地种子账号为 `admin / 123456`，密码必须以加盐 SHA-256 摘要保存。
- 错误账号或密码使用统一提示；连续失败 5 次锁定输入 30 秒。
- `QMainWindow` 使用左侧导航、右侧 `QStackedWidget`、顶部刷新/退出和底部状态栏。
- 默认账号仅允许 A 线隔离演示；不得部署到公网 B 线。

### 6.2 营收与设备总览（UC-A-03～04）

- 今日、本月和总营收仅统计 `status=2` 的已完成订单。
- 折线图支持近 7/30 日切换，柱状图显示同期每日订单量。
- 无数据时显示空坐标轴和“暂无数据”。
- 设备状态显示在用、闲置、故障的数量、百分比和饼图。
- 健康度 = `(空闲 + 使用中) / 总数 × 100%`。

### 6.3 充电桩管理（UC-A-05）

- 展示编号、站点、类型、功率、状态、累计次数和累计小时。
- 支持站点/状态筛选和编号搜索。
- 支持标记故障、恢复正常、新增和删除；使用中的设备禁止删除。
- 远程重启显示进度，2 秒后将故障设备恢复为空闲并记录运维日志。
- 对使用中设备重启必须二次确认；如何处理被中断订单仍需明确。

### 6.4 充电站管理（UC-A-06）

- 展示 ID、站名、地址、经纬度、单价、总电桩数和在线率。
- 查看站内设备；新增时可批量创建电桩，编号采用“站点缩写-序号”。
- 支持修改站名、地址、经纬度和单价。
- 有电桩时禁止删除；经纬度必须在合法范围内。

### 6.5 用户和预测管理（UC-A-07～08）

- 用户列表、手机号模糊搜索、冻结/解冻和订单历史属于必做。
- 冻结有进行中订单的用户时提示风险，但允许继续。
- 预测页读取 `load_prediction`，展示未来 1/6/24 小时负荷和空闲桩数。
- 通过 `QProcess` 运行 Python 预测；失败时提示并保留上次结果。
- 历史实际与模型预测使用折线图对比，高峰时段红色标注。

## 7. SQLite 数据库基线

### 7.1 必需表与一致性

- 必需表：`user`、`admin`、`station`、`charger`、`charging_order`、`ops_log`、`load_prediction`。
- `recharge_log` 在 SRS 中可选；为了可审计，推荐纳入基础实现。
- 使用 `schema_version` 管理迁移；首次启动自动建库，已有数据库不重复初始化。
- 开启外键与 WAL；预约、结算和批量建桩使用事务。
- UI 层不得包含 SQL；全部查询参数化，禁止拼接用户输入。

### 7.2 种子数据

- 1 个本地演示管理员。
- 至少 5 个不同坐标的电站。
- 每站 6～12 个快慢充混合电桩，包含 1～2 个故障设备。
- 约 30 天历史订单，确保营收图表和 ML 有数据可展示。

此前“三个北京站点、每站四桩”的方案不满足 SRS 最低数据量，需要调整或只用于 B 线小规模演示。

## 8. Web 大屏（UC-W）

- Vue 3 + ECharts，单页深色主题，1920×1080 基准并自适应缩放。
- 顶部显示平台名称和实时时钟。
- 左侧：设备状态饼图、站点充电量排行。
- 中间：总充电次数、总营收、在线桩数、注册用户数，以及近 30 日营收。
- 右侧：时段热力分布、快慢充占比和未来 24 小时负荷预测。
- A 线通过 `web/public/data/dashboard.json` 每 30 秒刷新；应采用原子替换避免读取半写文件。
- 图表支持悬浮提示、图例切换和数据截止时间。

B 线可以改为 HTTPS/WebSocket API，但不得破坏 A 线 JSON 导出验收方式。

## 9. 机器学习（UC-M）

- 按“电站、日期、小时”聚合历史订单。
- 特征包括小时、星期、周末、节假日、1/24/168 小时滞后、滑动均值、电站编码和模拟天气。
- 标签为每小时充电量。
- 第一版使用 `RandomForestRegressor`，固定随机种子，无需 GPU。
- 输出 MAE、RMSE、MAPE，并与“上周同一时刻”朴素基线比较；SRS 要求模型优于基线。
- 脚本支持 `--train`、`--predict`、`--evaluate`。
- 模型保存至 `ml/models/load_rf.pkl`，预测写入 `load_prediction`。
- LSTM、LightGBM、故障诊断、调度优化和风控属于后续扩展。

## 10. 非功能与验收

| 编号 | 指标 |
| --- | --- |
| NFR-P-01 | 不超过 100 个站点时，列表加载渲染小于 500ms |
| NFR-P-02 | 30 天营收聚合查询小于 300ms |
| NFR-P-03 | 充电页每秒刷新时 CPU 占用小于 5% |
| NFR-U-01 | 所有失败操作都有明确文字提示，禁止静默失败 |
| NFR-U-02 | 用户端 420×760；管理端最小 1280×800 |
| NFR-C-01 | 同一 CMake 工程可用 MSVC 2019 与 Ubuntu GCC 11 构建 |
| NFR-C-02/03 | 使用 Qt 跨平台路径；UTF-8；MSVC 加 `/utf-8` |
| NFR-M-01 | 单个源文件不超过 400 行 |
| NFR-M-02/03 | UI 无 SQL；数据库访问参数化 |
| NFR-M-04 | 日志写入 `logs/ncs_YYYYMMDD.log`，包含级别、时间、模块 |
| NFR-S-01/02 | 管理员密码加盐摘要；手机号展示时中间四位脱敏 |
| NFR-R-01/02 | 异常退出后恢复充电计费；数据库损坏时提示而非崩溃 |

最终验收至少提供用户端 5 类截图、管理端 4 类截图、Web 大屏、ML 曲线与指标、Ubuntu 编译运行终端截图。完整清单见 SRS 第 10 章。

## 11. 实施顺序

1. 冻结 A/B 双路线策略及差异清单中的 P0 决定。
2. 建立跨平台 CMake、共享领域模型、服务接口、日志与测试骨架。
3. 实现 SQLite 迁移、WAL、种子数据和数据库服务。
4. 完成 `ncs_user` 登录、站点、导航、资料、预约、充电、恢复和结算。
5. 完成 `ncs_admin` 登录、统计、设备、站点、用户和预测页面。
6. 完成 Python 训练/预测/评估与 Vue/ECharts 大屏。
7. 在 Ubuntu 22.04 验收并整理截图、测试报告与发布说明。
8. 基线稳定后扩展 Android、云端后端、PostgreSQL、即时排队和推送。
