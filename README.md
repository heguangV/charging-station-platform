# 电动汽车充电桩应用管理平台 NCS

## 1. 单一产品目标

本项目最终只建设一套完整系统。系统以 [软件需求规格说明书](docs/01-requirements-specification.md) 的文字功能、异常流、业务规则、非功能指标和交付内容为主体；只有在能显著改善 Android 支持、多客户端并发、云部署或安全性时，才采用等价技术替换。

详细需求冲突、仍未确定的规则和下一步问题统一维护在 [需求决策与未确定问题](docs/requirements-gap-analysis.md)。实现具体功能时必须回查对应 `UC-*`、`BR-*` 和 `NFR-*`，不能只依赖 README 摘要。

项目定位仍是教学、团队研发和功能演示系统：使用模拟充电桩、虚拟钱包和模拟支付，不连接真实电力设备，不处理真实资金。

## 2. 最终系统组成

| 子系统 | 最终技术与形态 | 主要职责 |
| --- | --- | --- |
| 车主用户端 | Qt Quick/QML + C++，Android 主目标并支持 Linux 桌面构建 | 登录、地图、导航、资料、充值、排队/预约、充电、结算、订单 |
| PC 管理端 | Linux Qt Widgets + Qt Charts | 营收、设备、站点、用户、订单、运维和预测管理 |
| 平台后端 | C++17 + Qt HTTP Server/Network/WebSockets | 认证、权限、业务规则、事务、设备模拟、实时消息和统计 API |
| 主数据库 | PostgreSQL + Qt SQL/QPSQL | 账号、站点、设备、队列、订单、计费、钱包、日志和预测数据 |
| 数据大屏 | Vue 3 + ECharts | 1920×1080 运营与预测看板 |
| 智能分析 | Python 3.10+ + scikit-learn | 数据聚合、训练、评估、预测和结果回写 |
| 公网入口 | Ubuntu Server 24.04 + Nginx + TLS | HTTPS/WSS 入口、静态大屏、访问控制和日志 |

开发环境使用 VMware 17、Ubuntu 22.04 或更高版本、Qt 6.8.3、CMake、Ninja 和 C++17。桌面 C++ 部分保持跨平台代码，能在 Windows/MSVC 与 Ubuntu/GCC 构建；正式部署和 PC 管理端以 Linux 为目标。

## 3. 等价增强决策

| SRS 原方案 | 最终方案 | 替换理由 | 必须保持的行为 |
| --- | --- | --- | --- |
| Qt Widgets 手机竖屏用户端 | Qt Quick/QML Android/Linux 共用用户端 | 显著提高移动端适配和界面复用 | 竖屏布局、所有 `UC-U` 页面、异常流和验收内容 |
| 两个程序共享 SQLite 文件 | C++/Qt 后端 + PostgreSQL | 支持 Android、云端、多用户并发和事务控制 | 表达相同数据关系、种子数据、事务一致性和恢复能力 |
| 客户端直接访问数据库 | HTTPS REST + WebSocket | 避免公开数据库并集中权限和规则 | 查询、刷新和实时状态必须达到原功能效果 |
| 大屏轮询本地 JSON | API/WebSocket 为主，保留 `dashboard.json` 导出 | 实时性更好，同时保留离线演示能力 | 原布局、30 秒内刷新、数据截止时间和空数据处理 |
| 本地时间字符串 | PostgreSQL UTC 时间戳，客户端显示本地时间 | 避免时区和字符串比较问题 | 用户看到的时间与 SRS 本地时间语义一致 |
| 金额直接保存为元 | 数据库保存整数分，API/界面显示元和两位小数 | 避免浮点累计误差 | 所有金额范围、公式和小票显示一致 |
| 加盐 SHA-256 管理员密码 | 专用密码哈希，优先 Argon2id；不可用时使用成熟等价方案 | 显著提高公网账号安全 | 默认演示账号只在开发环境提供，错误提示和锁定规则保留 |

腾讯地图、RandomForest、Qt Charts、Haversine、ECharts 和 SRS 指定的核心业务流程不替换。

## 4. 用户角色与权限

最终保持三个角色：

| 角色 | 权限 |
| --- | --- |
| 车主用户 | 使用 Android/Linux 用户端管理自己的资料、钱包、排队、预约、充电和订单 |
| 运营管理员 | 使用 PC 管理端管理站点、设备、用户、订单，查看营收和预测，执行模拟运维 |
| 决策查看者 | 只读访问数据大屏和汇总指标，不执行业务修改 |

权限由后端校验，不能仅依靠客户端隐藏按钮。第一个运营管理员通过服务器初始化命令创建；开发环境可以生成 `admin / 123456` 演示账号，但必须强制首次修改，公网配置禁止默认密码。

## 5. 全局业务规则

- 手机号必须为以 1 开头的 11 位数字且全局唯一；用户名也全局唯一。
- 一个用户同一时间最多有一个排队、待确认、已预约或充电中的活动流程。
- 一个充电桩同一时间最多被一个待确认分配、预约或充电会话占用。
- 余额达到最低起充金额才能预约或开始充电，默认门槛 5 元。
- 故障、重启中、停用设备不能被分配、预约或开始充电。
- 金额使用整数分，电量使用明确精度的定点 kWh，时间在服务端保存 UTC。
- 预约、设备分配、开始、结束、结算、充值、余额调整和运维命令必须支持事务、幂等和审计。
- 订单、充电会话和钱包流水不物理删除；账号注销后匿名保留必要业务凭证。
- 后端和 PostgreSQL 是设备、排队、订单、计费与余额的唯一可信来源。

## 6. 账号、登录和用户中心

### 6.1 注册与登录

- 用户注册时填写唯一用户名、11 位手机号和密码；手机号由必填改为遵循 SRS 的必填规则。
- 支持“用户名 + 密码”或“手机号 + 密码”登录。
- 为覆盖 SRS 的验证码自动注册演示，开发配置提供 6 位模拟验证码流程：获取后按钮倒计时 60 秒，验证码直接显示在开发界面；公网配置禁止返回验证码。
- 模拟验证码默认 10 分钟有效、最多尝试 5 次，获取新码后旧码立即失效。
- 冻结用户不能登录或发起新充电；登录失败必须给出统一、安全的提示。
- 只有绑定手机号的用户可以使用模拟验证码重置密码。

### 6.2 用户资料

- 新用户默认余额为 0，默认昵称为“用户 + 手机号后 4 位”，显示默认灰色头像。
- 展示头像、昵称、脱敏手机号、钱包余额和注册时间。
- 昵称长度 1～20，禁止纯空白。
- 头像支持 PNG/JPG/JPEG/BMP，最大 5MB；文件存储在服务器受限目录或对象存储，数据库保存受控引用。
- 修改资料后立即持久化并能在重新登录后恢复。
- 用户可退出登录和申请注销；注销撤销全部令牌并清除手机号、密码等登录凭据。

### 6.3 虚拟钱包

- 模拟充值范围 0.01～10000 元，最多两位小数，不调用真实支付。
- 每次充值、扣费、退款、欠费和管理员调整均产生不可变钱包流水。
- 管理员调整必须填写原因并记录审计日志。
- 页面明确标注“虚拟余额”，不支持提现。

## 7. 地图、站点与导航

- 第一阶段数据限定北京市，但种子数据至少包含 5 个站点，不再使用三个站点、每站四桩的旧规模。
- 每站包含 6～12 个快慢充混合设备，并提供 1～2 个故障设备用于管理演示。
- 支持区域选择、地址输入和软件模拟位置。
- 配置腾讯地图 Key 且联网时进行地理编码；失败时使用预置坐标。
- 使用 Haversine 计算直线距离并按距离升序排列。
- 站点卡片显示名称、总单价、空闲数/总数和距离；详情显示地址、价格、设备编号、类型、功率、状态和累计次数。
- 导航支持驾车、步行和公交；优先在 WebView/WebEngine 内加载腾讯地图，失败时显示坐标/距离并用系统浏览器打开路线链接。
- 地图失败、空站点和网络超时必须明确提示，不能空白假死。

此前申请的高德 Key 暂不作为主实现；只有确认腾讯地图无法满足项目需求时，才评估等价替换。

## 8. 排队、预约、充电与结算

### 8.1 排队与预约

- 有兼容空闲设备时，用户可以直接预约；预约保留 15 分钟，超时未开始则取消并释放设备。
- 没有空闲设备时进入即时队列，不支持选择未来日期或时间段预约。
- 队列轮到用户后通过 WebSocket/TPNS 通知，并提供 5 分钟确认期。
- 用户确认分配后创建 15 分钟预约；5 分钟未确认则释放分配并递补下一位。
- 队列顺序、设备分配和倒计时均以后端时间为准。

### 8.2 充电前拦截

- 进入选桩前查询排队、待确认、预约、充电中和待结算状态。
- 已充电中的用户进入当前充电控制页继续计费；待结算用户强制进入结算页。
- 其他活动状态进入对应队列或预约页，不允许重复创建流程。

### 8.3 实时充电

- 开始充电时记录价格与时间倍率快照，订单/会话进入充电中状态。
- 每秒展示时长、电量、费用、实时功率和模拟 SoC。
- 电量按功率和模拟时长累积；时间倍率默认 60、可配置范围 1～300，只影响新会话。
- 程序退出、网络断开或手机进入后台后，后端继续计费；重新连接后恢复正确状态。
- 用户可以手动结束，也可以设置不限金额、10/20/30 元或 1～500 元目标金额自动结束。

### 8.4 价格与结算

- 每个站点保存电费单价和服务费单价，总单价为两者之和；北京种子数据默认使用统一价格，但保留管理端按站点修改能力。
- `电费 = 电量 × 电费单价`，`服务费 = 电量 × 服务费单价`，总额为两者之和。
- 系统在预计达到目标金额或余额上限时自动停止，正常流程不产生欠费。
- 因计时步长或并发造成少量超额时，余额扣至 0，并记录欠费金额，保留 SRS 的兜底规则。
- 结束时在同一事务内写订单、释放设备、更新设备累计次数/时长、扣减余额和生成流水；任一步失败整体回滚。
- 小票显示订单号、站点、设备、起止时间、时长、电量、费用明细、总额和余额。
- 历史订单按时间倒序，可查看详情和状态。

## 9. PC 管理端

### 9.1 界面与登录

- 使用 `QMainWindow`、左侧导航、右侧 `QStackedWidget`、顶部刷新/退出和底部状态栏。
- 最小分辨率 1280×800，深色科技风可参考原说明图片但不要求复刻。
- 管理员账号密码错误使用统一提示；连续失败 5 次锁定登录 30 秒。

### 9.2 营收与状态

- 显示今日、本月、总营收，只统计已完成订单。
- 近 7/30 日营收折线图和同期每日订单量柱状图；无数据时显示空坐标与提示。
- 显示空闲、使用中、故障状态数量、比例和饼图。
- 设备健康度 = `(空闲 + 使用中) / 总数 × 100%`。

### 9.3 设备、站点、用户与订单

- 设备列表、筛选、编号搜索、新增、故障/恢复、模拟远程重启和受控删除。
- 远程重启显示 2 秒进度并写运维日志；使用中设备默认禁止重启，除非后续明确中断订单规则。
- 站点支持新增、修改和受控删除；新增站点可以批量生成设备，经纬度必须合法。
- 有设备或历史业务数据的站点不物理删除，改为停用。
- 用户支持手机号模糊搜索、冻结/解冻和订单历史查看。
- 冻结用户不终止进行中的充电，但仍允许查看、结束和结算；禁止创建新流程。
- 订单支持按编号、用户、站点、设备、状态和时间查询。

### 9.4 智能预测

- 展示各站未来 1/6/24 小时预测负荷、空闲桩数和高峰标记。
- 对比历史实际与预测曲线。
- 管理端请求后端启动 Python 任务；失败时提示并保留上一次成功结果。

## 10. 数据库与种子数据

PostgreSQL 至少包含以下领域数据：

- 用户、角色、管理员、登录会话、验证码和推送设备令牌。
- 充电站、充电桩、设备状态历史、设备命令和运维日志。
- 排队项、待确认分配、预约、充电会话、订单和计费明细。
- 钱包账户、充值记录、钱包流水、欠费和管理员调整。
- 系统配置、审计日志、服务器指标和备份记录。
- 预测样本、特征版本、模型版本、评估指标和 `load_prediction` 结果。

所有结构变化使用版本化迁移，空库可以迁移并播种。种子数据固定随机种子，至少生成：

- 1 个开发管理员和必要的只读查看账号。
- 北京至少 5 个站点。
- 每站 6～12 个设备，快慢充混合，含 1～2 个故障设备。
- 约 30 天历史订单、充值、状态和预测演示数据。

数据库只允许后端访问，公网不开放 5432；开发、测试和云端凭据隔离。

## 11. Web 数据大屏

- Vue 3 + ECharts，1920×1080 深色单页并自适应缩放。
- 顶部显示平台名称、环境标识和实时时钟。
- 左侧显示设备状态占比和站点充电量排行。
- 中间显示总充电次数、总营收、在线设备、注册用户和近 30 日营收趋势。
- 右侧显示充电时段热力图、快慢充占比和未来 24 小时负荷预测。
- API 初次加载，WebSocket 推送更新；断线时每 30 秒轮询。
- 后端同时原子导出版本化 `dashboard.json`，用于离线演示和故障降级。
- 图表支持悬浮、图例切换、数据截止时间、加载、空数据和错误状态。
- 决策查看者只读访问；具体登录方式仍待确认。

## 12. 机器学习智能分析

- 按“站点、日期、小时”聚合充电订单。
- 特征包含小时、星期、周末、节假日、1/24/168 小时滞后、滑动均值、站点编码和模拟天气。
- 标签为每小时充电量。
- 第一版使用 `RandomForestRegressor`，固定随机种子，无需 GPU。
- 使用按时间顺序的训练/验证/测试切分，避免数据泄漏。
- 输出 MAE、RMSE、MAPE，并与上周同一时刻朴素基线比较。
- 脚本支持 `--train`、`--predict`、`--evaluate`；模型保存在 `ml/models/load_rf.pkl`。
- 预测写回 PostgreSQL，包含站点、生成时间、目标时间、负荷、空闲数和高峰标记。
- 模型或脚本失败时继续提供最近一次成功结果，并显示更新时间和失败提示。

LSTM、LightGBM、设备故障诊断、调度优化和智能风控不属于当前单一目标。

## 13. 通信、并发与通知

- REST 使用版本化路径、统一 JSON、请求 ID、稳定错误码和幂等键。
- WebSocket 推送充电、设备、队列、管理统计和预测状态；断线自动重连并重新查询快照。
- 网络、数据库、设备模拟、文件和 ML 任务不得阻塞 UI 或服务器事件线程。
- 使用 Qt 跨平台线程与网络封装完成 Socket/并发要求，不直接依赖 POSIX 专有 API。
- TPNS 仅用于队列分配、预约到期等系统提醒；推送内容不包含手机号、余额或完整订单。
- 用户拒绝通知权限或推送失败时，App 内仍可查询完整状态。

## 14. 安全、错误、日志和备份

- 密码使用专用密码哈希；刷新令牌、验证码只保存安全摘要。
- 手机号展示时中间四位脱敏；日志不记录完整手机号、令牌、验证码或密钥。
- 地图、TPNS、数据库和云凭据只存服务器环境或受限配置，不进入源码、APK、GitHub 和日志。
- 所有输入、权限、状态和金额由后端校验；数据库查询全部参数化。
- 所有失败操作提供明确文字提示；覆盖无权限、状态冲突、余额不足、数据库、网络、地图、推送和 ML 失败。
- 日志包含时间、级别、模块、请求 ID，执行轮转和保留策略。
- PostgreSQL 每日备份保留 7 份、每周备份保留 4 份，并至少完成一次测试恢复。
- Nginx 提供 TLS；公网只开放必要端口。

## 15. 非功能指标

- 不超过 100 个站点时，列表加载和渲染小于 500ms。
- 30 天营收聚合查询小于 300ms。
- 充电页每秒更新，在目标设备上 CPU 占用原则上小于 5%。
- Android 用户端适配竖屏；Linux 用户端保持约 420×760 手机比例；管理端最小 1280×800。
- 源文件使用 UTF-8，路径通过 Qt 跨平台 API 构造；MSVC 使用 `/utf-8`。
- 单个手写源文件原则上不超过 400 行，UI 不包含 SQL。
- 用户端、管理端、后端、大屏和 ML 都必须具备加载、空数据、失败和恢复状态。
- 当前规模目标至少支持 100 个站点；注册用户、在线用户和并发充电目标仍待确认。

## 16. 实施阶段

以下阶段共同组成最终目标：

1. 冻结未确定业务规则、状态机、API 与数据库模型。
