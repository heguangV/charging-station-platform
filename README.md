# 充电桩管理系统

## 1. 项目定位

本项目是用于教学、团队研发和功能演示的充电桩管理原型。首期完成 Android 用户端、Linux 管理端、云端后端与 PostgreSQL 数据库之间的真实通信，并通过模拟充电桩形成完整业务闭环。

首期不连接真实充电桩，不处理真实资金，也不作为可直接商用的系统。真实设备、真实短信、在线支付和正式合规上线属于后续能力。

## 2. 已确认的总体范围

| 项目 | 已确认决定 |
| --- | --- |
| 移动端 | 仅支持 Android，使用 Qt Quick/QML + C++ |
| PC 管理端 | 仅支持 Linux，使用 Qt Widgets + C++；首期不制作安装包 |
| 后端 | C++/Qt，提供 REST API 与 WebSocket |
| 数据库 | PostgreSQL，通过 Qt SQL/QPSQL 访问 |
| 开发环境 | VMware NAT 虚拟机，Ubuntu 22.04 LTS x86_64 |
| 部署环境 | Ubuntu Server 24.04 LTS 云服务器，后端与 PostgreSQL 同机部署 |
| 地图 | 高德地图 JS API + Qt WebView，仅模拟北京市 |
| Android 标识 | 包名 `io.github.heguangv.chargingstation` |
| 消息提醒 | WebSocket 实时消息 + 腾讯云 TPNS 基础推送 |
| 项目许可 | GitHub Public 公开仓库，GPL-3.0 |
| 代码仓库 | `https://github.com/heguangV/charging-station-platform` |
| 预估规模 | 已提出约 10–100 的范围，具体指标仍需确认 |

云服务器地址、高德密钥、数据库凭据和其他部署机密通过环境配置提供，不写入公开仓库。

## 3. 用户角色与权限

第一版设置三个角色，权限必须由后端校验，不能只依靠客户端隐藏按钮。

| 角色 | 主要权限 |
| --- | --- |
| 普通用户 | 使用 Android 端查询站点、发起充电、管理虚拟余额和查看自己的订单 |
| 运营人员 | 使用 Linux 管理端查看站点、设备、订单、用户状态和运营数据 |
| 系统管理员 | 管理站点、设备、运营账号、用户状态、虚拟余额、系统配置、服务器状态和备份 |

第一个系统管理员通过服务器初始化命令创建，不提供公开注册。系统管理员可以创建、停用和重置运营人员账号；运营人员不能创建管理员。管理员首次登录后必须修改初始密码。

## 4. Android 用户端需求

### 4.1 注册、登录与账号

- 用户名必填且唯一，手机号选填，填写后必须唯一。
- 用户可使用“用户名 + 密码”或“手机号 + 密码”登录。
- 密码只保存可靠算法生成的加盐摘要。
- 不收集昵称、真实姓名、身份证、性别、生日、住址、车牌和位置历史。
- 保存用户协议与隐私说明的确认状态和时间。
- Android 登录状态保持 7 天，使用短期访问令牌和刷新令牌。
- 退出、修改密码、账号停用或注销后撤销旧令牌。

### 4.2 模拟密码重置

- 只有绑定手机号的用户可以使用模拟密码重置。
- 后端生成 6 位模拟验证码，有效期 10 分钟，最多尝试 5 次。
- 数据库只保存验证码摘要、有效期和尝试次数。
- 开发模式明确显示“模拟验证码，仅用于开发演示”；生产配置禁止返回验证码。
- 保留 SmsProvider 接口，未来可替换为真实短信服务。

该流程不能证明用户真实持有手机号，不具备商用账号安全能力。

### 4.3 地图与站点

- 使用高德地图 JS API，通过 Qt WebView 嵌入 QML 页面。
- 地图默认中心为北京市。
- 第一版包含朝阳区、海淀区和丰台区三个模拟站点。
- 每个站点配置 4 个模拟充电桩，共 12 个设备。
- 地图标记展示站点名称、模拟地址和空闲设备数，点击进入站点详情。
- 用户授权后显示当前位置并计算站点距离；拒绝权限时仍可浏览地图。
- 不长期保存精确位置，第一版不提供路线规划和导航。
- 高德 Key 与安全密钥保存在项目外；正式部署时安全密钥由服务器代理使用。

### 4.4 设备选择与充电

- 用户可从地图或站点列表选择设备，也可手动输入设备编号。
- 第一版不开发二维码扫描，不申请摄像头权限。
- 开始前展示设备、站点、功率、统一价格、虚拟余额和目标金额。
- 充电页面每秒更新模拟时长、充电量、电费、服务费和总额。
- 后端是充电状态和最终计费的唯一可信来源。

### 4.5 订单、余额与注销

- 用户查看当前充电、历史订单、虚拟余额和余额流水。
- 新用户注册后赠送 100 元虚拟余额。
- 用户可模拟充值 50、100、200 元或自定义金额，不调用真实支付。
- 系统管理员可调整余额，但必须填写原因并记录审计日志。
- 页面明确标注“虚拟余额”，不代表真实资金，不支持提现。
- 用户注销后删除密码、手机号和登录令牌，历史订单、会话和余额流水匿名保留。

### 4.6 预约、排队与通知

- 第一版纳入预约排队功能；没有可用设备时，用户可进入对应站点或设备类型的等待队列。
- 后端维护队列顺序与分配结果，客户端显示当前位置和当前状态，但不能自行决定排队顺序。
- 轮到用户后，后端记录设备分配和 5 分钟确认期限；超时未确认时释放名额并继续处理队列。
- 在线客户端通过 WebSocket 接收状态变化，后台或离线客户端通过腾讯云 TPNS 基础通道接收系统通知。
- 点击通知进入预约确认页面；页面必须重新查询后端，推送消息不能作为预约状态的唯一依据。
- 第一版暂不接入华为、小米、OPPO、vivo 等厂商专用推送通道，保留后续配置接口。
- 用户拒绝通知权限或推送失败时，仍可在 App 内查询预约和排队状态。

## 5. Linux 管理端需求

- 仅运营人员和系统管理员可以登录，登录会话保持 8 小时。
- 仪表盘展示用户数、在线用户、站点数、设备数、空闲/充电中数量、当日充电量、订单数、虚拟收入及最近 7 天趋势。
- 管理站点、充电桩、用户状态、模拟余额、运营账号和系统配置。
- 按订单号、用户、站点、设备、状态和时间查询订单。
- 查看充电会话、计费快照、余额流水和审计日志。
- 系统管理员可修改统一价格、模拟倍率并触发手动备份。
- 查看服务版本、运行时长、数据库连接、CPU、内存、磁盘、在线用户、进行中会话和最近备份。

第一版不开发复杂财务报表、Excel 导出、设备异常模拟和告警处理页面。

## 6. 模拟充电桩

- 第一版没有真实设备或厂商协议，使用独立模拟器并保留设备通信接口。
- 设备只实现“空闲”和“充电中”两个主要状态。
- 同一设备同一时间只能存在一个有效充电会话。
- 不模拟离线、故障、维护、启动失败、远程升级和异常告警。
- 充电量根据设备功率、经过时间和模拟倍率计算。
- 模拟倍率表示“现实 1 秒对应多少模拟秒”，默认 60，允许范围 1～300。
- 只有系统管理员可修改倍率，修改只影响新会话；会话保存启动时的倍率快照。
- 每次修改记录操作人、修改前值、修改后值和时间。

## 7. 计费、目标金额与虚拟余额

第一版全北京市使用统一价格，不按站点、设备或时段区分。

```text
充电费用 = 充电量 × 电费单价
服务费用 = 充电量 × 服务费单价
订单总额 = 充电费用 + 服务费用
```

- 金额以“分”为单位保存，充电量使用明确精度的定点值。
- 会话保存电费、服务费和倍率快照；修改配置不影响历史订单或进行中会话。
- 第一版不计算停车费，不处理峰谷分时价格。
- 用户可选择不限金额、10 元、20 元、30 元或 1～500 元自定义目标金额。
- 用户可手动结束；达到目标金额或余额上限时由后端自动结束。
- 目标金额不得超过余额；不限金额时余额就是最大消费上限。
- 订单结算、余额扣减和流水写入使用同一事务，并具备幂等保护。

电费和服务费的具体演示单价尚未最终确认。

## 8. 后端、通信与公网安全

- 使用 C++17、Qt 6.8 或更高版本。
- Qt HTTP Server 提供版本化 REST API、统一 JSON 格式和错误模型。
- Qt WebSockets 每秒推送充电进度和实时仪表盘数据。
- 后端通过腾讯云 TPNS 服务端接口发送预约提醒，TPNS 密钥仅保存在服务器环境中。
- Android 端通过少量原生桥接代码接入 TPNS SDK，并在用户同意隐私政策后初始化和申请通知权限。
- 推送内容不包含手机号、余额或完整订单信息；推送发送失败只记录结果，不改变后端预约事实。
- WebSocket 断线后自动重连，并从后端重新获取当前状态。
- 后端完成认证、角色权限、业务校验、事务、幂等、审计和数据访问。
- Android 与管理端不得直接连接 PostgreSQL。
- 网络请求和数据库访问不得阻塞客户端 UI 线程。
- 云服务器使用 Nginx 作为公网入口和 TLS 终止点。
- 使用 Let’s Encrypt 公网 IP 短期证书并自动续期；获得域名后迁移到域名证书。
- 公网只开放必要的 SSH、HTTP 证书验证和 HTTPS 端口。
- 后端内部端口和 PostgreSQL 5432 不直接开放公网。
- 客户端必须验证 TLS 证书，禁止忽略 SSL 错误。

## 9. PostgreSQL 数据需求

PostgreSQL 是确定的主数据库，不再评估 SQLite 作为第一版主数据库。开发、测试和云端部署使用相互隔离的数据库及凭据。

| 数据对象 | 核心信息 |
| --- | --- |
| 用户 | ID、用户名、可选手机号、密码摘要、角色、状态、协议确认和时间字段 |
| 登录会话 | 用户、刷新令牌摘要、客户端、创建、过期和撤销时间 |
| 验证码 | 用户、手机号脱敏标识、验证码摘要、有效期、尝试次数和状态 |
| 设备推送令牌 | 用户、平台、设备标识摘要、TPNS Token、启用状态和最后活跃时间 |
| 管理员 | 账号、角色、状态、首次改密标记和最后登录时间 |
| 充电站 | ID、名称、行政区、模拟地址、经纬度和营业状态 |
| 充电桩 | ID、编号、站点、接口类型、功率和业务状态 |
| 预约与队列 | 用户、站点/设备类型、队列序号、分配设备、确认期限、状态和时间 |
| 充电会话 | 用户、设备、起止时间、倍率、目标金额、充电量、价格快照、费用和状态 |
| 订单 | 订单号、会话、计费明细、总金额、结算状态和时间 |
| 余额账户 | 用户、当前虚拟余额和版本号 |
| 余额流水 | 用户、类型、金额、变动前后余额、关联 ID 和时间 |
| 服务器实例 | 实例 ID、版本、环境、启动时间、心跳和健康状态 |
| 服务器指标 | CPU、内存、磁盘、在线用户、进行中会话和采集时间 |
| 系统配置 | 配置名、版本、值、状态、更新时间和修改人 |
| 审计日志 | 操作人、类型、目标、结果、来源和时间 |

数据设计要求：

- 明确主键、外键、唯一、非空、检查约束、索引和删除策略。
- 用户名唯一；手机号非空时唯一。
- 使用参数化查询；数据库访问封装在基础设施层。
- 所有结构变化通过带版本号的迁移执行，空库可完整迁移。
- 订单、会话与余额流水不物理删除；注销后匿名保留。
- 密码、私钥、令牌、高德安全密钥等机密不进入普通配置表或日志。

## 10. 监控、日志与备份

- 后端每 60 秒采集服务器指标，指标保留 7 天。
- 普通运行日志保留 30 天，管理员审计日志保留 180 天。
- 订单、充电会话和余额流水长期保留。
- 服务启动、停止、异常和备份结果作为事件长期保留。
- PostgreSQL 每天备份，保留最近 7 个每日备份；每周额外保留一个，共 4 周。
- 第一版备份只保存在云服务器本机受限目录，并至少验证一次恢复到测试数据库。

同机备份不能防止整台服务器或磁盘丢失，异地备份属于后续能力。

## 13. MVP 端到端流程

1. 初始化系统管理员，并创建三个北京模拟站点和 12 个设备。
2. 用户在 Android 端注册，获得 100 元虚拟余额。
3. 用户通过高德地图或列表查看站点、距离和空闲设备。
4. 设备繁忙时用户加入队列；后端分配设备并通过 WebSocket/TPNS 提醒用户在 5 分钟内确认。
5. 用户选择或确认设备，设置不限金额、快捷金额或自定义目标金额。
6. 后端创建会话，模拟器生成充电量，WebSocket 每秒推送进度。
7. 用户手动结束，或达到目标金额/余额上限后自动结束。
8. 后端在事务中生成订单、扣减余额并写入流水。
9. 用户查看订单与流水；管理员查看仪表盘和审计日志。
10. 管理员修改价格或倍率，验证只影响新会话。
11. 系统执行数据库备份并恢复到测试数据库。

至少测试重复启动、同设备并发启动、重复结束、重复扣款、余额不足、令牌失效、WebSocket 重连和事务回滚。
