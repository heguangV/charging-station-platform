# NCS 充电桩平台开发

## 需求路由

开始工作前阅读仓库根目录的 [README](../../../README.md)。实现具体功能时读取 [SRS 原文](../../../docs/01-requirements-specification.md) 中对应的 `UC-*`、`BR-*`、`NFR-*`；涉及仍未冻结的规则时读取 [需求决策与未确定问题](../../../docs/requirements-gap-analysis.md)。

项目只有一个最终目标。SRS 的业务行为和可观测结果是主体；只有显著改善 Android、多客户端并发、云部署或安全性时才采用等价技术替换，并保留原功能效果。

## 最终技术目标

- Android/Linux 车主用户端使用 Qt Quick/QML + C++；Android 包名为 `io.github.heguangv.chargingstation`。
- Linux PC 管理端使用 Qt Widgets + Qt Charts。
- C++17/Qt 后端提供版本化 HTTPS REST 与 WebSocket。
- PostgreSQL 是唯一主数据库，客户端和大屏不得直接连接。
- Vue 3 + ECharts 提供运营大屏；Python/scikit-learn RandomForest 提供预测。
- Ubuntu Server 24.04 部署 Nginx、后端、PostgreSQL、大屏和 ML；Ubuntu 22.04+ 用于开发与验证。
- 腾讯地图为主地图服务，并保留预置坐标、Haversine 和浏览器导航降级。

## 等价增强不变量

- QML 必须覆盖 SRS 全部 `UC-U` 页面、异常流和竖屏交互，不得因替换 Widgets 缩减功能。
- PostgreSQL/API 必须覆盖 SRS 的数据关系、种子数据、事务、恢复与统计结果，不再实现 SQLite 主版本。
- 大屏使用 API/WebSocket，同时保留版本化 JSON 原子导出作为离线降级。
- 数据库金额用整数分、时间用 UTC；界面仍按元、两位小数和本地时间展示。
- 密码使用专用密码哈希；`admin/123456` 和界面展示的模拟验证码只允许开发配置。
- Qt 网络和线程封装满足 Socket/并发目标，不直接依赖 pthread/POSIX 专有 API。

## 核心产品规则

- 三角色为车主用户、运营管理员和决策查看者；权限由后端校验。
- 注册需要唯一用户名、必填唯一手机号和密码；支持用户名/手机号密码登录。开发配置另提供模拟验证码自动注册。
- 恢复昵称、头像、手机号脱敏和余额 0 的 SRS 用户资料规则。
- 北京至少 5 个站点，每站 6～12 个快慢充设备，并含故障设备和历史数据。
- 有空闲设备时直接预约 15 分钟；无空闲设备时即时排队，轮到后 5 分钟确认，再创建预约。
- 一个用户最多一个活动充电流程，一个设备最多一个活动占用；分配与状态转换由后端事务控制。
- 充电默认倍率 60、范围 1～300；后端持续计费并在重连后恢复。
- 每站保存电费和服务费；种子数据默认全市统一，预约时保存价格快照。
- 用户可手动或按目标金额/余额上限结束；正常流程避免欠费，少量超额记录欠费。
- 结算、余额扣减、钱包流水、设备释放和统计更新在同一事务中幂等完成。
- 管理端、大屏和 ML 的页面、指标、预测特征和异常行为按 README/SRS 实现。

## 工程边界

- `apps/mobile`：Android/Linux QML 用户端。
- `apps/admin`：Linux Widgets 管理端。
- `apps/server`：REST、WebSocket、认证、调度、模拟计费和统计。
- `apps/dashboard`：Vue/ECharts 大屏。
- `core/domain`、`core/application`：领域模型、用例、状态机和接口。
- `infrastructure/postgres`：迁移、仓储与事务。
- `infrastructure/map`、`push`、`files`：地图、TPNS 和文件服务。
- `ml`：数据准备、训练、预测、评估与模型版本。
- `tests`：领域、数据库、API、并发、恢复、UI 烟雾和端到端测试。

UI 不包含 SQL、权限、计费或余额扣减规则。网络、数据库、文件和 ML 任务不得阻塞 UI 或后端事件线程。

## 安全与数据不变量

- 所有输入参数化查询；跨表操作使用事务、幂等键和审计日志。
- 故障、重启中、停用设备不可分配；使用中设备默认禁止远程重启。
- 价格和倍率保存会话快照；配置修改不影响历史和进行中会话。
- 订单、会话和钱包流水不物理删除；注销后匿名保留业务凭证。
- 令牌、验证码和密码只保存安全摘要；完整手机号、令牌、验证码和密钥不写日志。
- 地图、TPNS、数据库和云服务密钥不进入源码、APK、GitHub 或普通配置表。
- 网络、地图、推送、数据库和 ML 失败必须有明确提示、重试或降级，不静默失败。

## 完成标准

- 每项实现可追踪到 README、SRS 用例或明确的等价增强决策。
- PostgreSQL 可从空库迁移并生成至少 5 站、每站 6～12 桩和历史数据。
- 用户端、管理端、后端、大屏与 ML 形成一个可部署、可恢复的完整系统。
- 并发分配、重复请求、计费恢复、事务回滚、余额边界和权限得到测试。
- 满足 SRS 的主要性能、尺寸、日志、错误提示、跨平台和截图/指标要求。
- 文档只描述这一单一目标，并如实标记未完成与未确定问题。
