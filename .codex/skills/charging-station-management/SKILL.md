# 充电桩管理系统开发

## 需求来源

开始项目工作前先阅读仓库根目录的 [README](../../../README.md)。其中“已确认”内容是产品基线，“尚未解决的问题”是待确认清单。不要用旧原型覆盖已确认需求，也不要替用户决定仍未解决的计费、预约、设备、部署和验收规则。

## 已确认的产品基线

- 项目定位为教学与团队研发使用的内部演示原型，不直接作为商用系统。
- Android 用户端使用 Qt Quick/QML + C++；Linux 管理端使用 Qt Widgets + C++。
- 后端使用 C++17、Qt HTTP Server、Qt WebSockets、Qt Network 和 Qt SQL/QPSQL。
- PostgreSQL 是确定的主数据库；客户端不得直接连接数据库。
- VMware Ubuntu 22.04 用于开发测试；Ubuntu Server 24.04 云服务器用于部署 Nginx、后端和 PostgreSQL。
- 公网使用 Nginx 与可信 TLS 证书；服务器地址和机密通过环境配置提供，不进入公开仓库。
- 地图使用高德 JS API + Qt WebView，范围限定为北京，支持授权定位和距离，不做导航。
- Android 包名是 `io.github.heguangv.chargingstation`；公开仓库是 `https://github.com/heguangV/charging-station-platform`。
- 第一版只支持设备繁忙后的即时排队，不支持选择未来日期或时间段提前预约。
- 后端分配设备后给用户 5 分钟确认，并通过 WebSocket 与腾讯云 TPNS 基础通道提醒。
- 推送仅用于提醒，排队与分配状态始终以后端查询结果为准；第一版不接厂商专用推送通道。
- 第一版包含朝阳、海淀、丰台三个模拟站点，每站四个设备；最终坐标与设备规格仍待确认。
- 角色为普通用户、运营人员和系统管理员，权限由后端校验。
- 用户名必填，手机号选填；两者均可作为密码登录标识。用户资料不包含昵称。
- 手机号密码重置使用明确标注的模拟验证码，不具备真实短信安全性。
- Android 登录保持 7 天，管理端保持 8 小时；退出、改密、停用和注销需要撤销令牌。
- 第一版使用统一电费与服务费、虚拟余额和模拟充值，不使用真实资金。
- 新用户赠送 100 元虚拟余额；余额变化必须有流水，结算、扣款和流水写入使用同一事务并保证幂等。
- 用户可手动停止，或按不限金额、10/20/30 元、1～500 元自定义目标金额自动停止。
- 模拟时间倍率默认 60，允许 1～300，只影响新会话并保存到会话快照。
- 第一版不连接真实设备，不模拟故障、离线或维护；设备只实现空闲和充电中主流程。
- 第一版不做二维码、真实短信、真实支付、导航、峰谷计费、停车费、安装包、离线使用和异地备份。
- 仓库计划公开托管在 GitHub，采用 GPL-3.0、main + feature/* + Pull Request。

## 架构边界

按仓库现状逐步迁移到以下逻辑边界，不在一次无关改动中强制完成整仓重排：

- apps/mobile：Android 入口、QML 页面、定位与平台适配。
- apps/admin：Linux Widgets 管理端。
- apps/server：REST、WebSocket、认证中间件、任务调度和服务器指标采集。
- core/domain：用户、权限、站点、设备、充电会话、价格、订单、余额和审计模型。
- core/application：用例编排、事务边界和接口定义。
- infrastructure：PostgreSQL 仓储与迁移、高德代理、模拟器、日志和配置实现。
- tests：领域单元测试、数据库集成测试、API 契约测试和端到端烟雾测试。

移动端、管理端和后端共享协议与领域语义，但保持进程、权限、UI 和发布边界。UI 不直接包含计费、权限、余额扣减或 SQL 规则。

## 关键业务不变量

- 同一设备同一时间最多有一个有效充电会话。
- 同一设备不能同时分配给多个待确认用户；排队顺序、分配和 5 分钟确认期限由后端控制。
- 推送失败、通知权限被拒绝或客户端离线不得改变排队和分配事实，用户重新进入 App 后必须能查询当前状态。
- 后端和 PostgreSQL 是状态、余额、订单和计费的唯一可信来源。
- 金额使用最小货币单位的整数；充电量使用明确精度的定点表示。
- 会话保存价格和模拟倍率快照，配置修改不影响历史订单或进行中会话。
- 目标金额不得超过余额；不限金额时余额是消费上限。
- 开始、结束、结算和余额调整接口必须支持幂等。
- 订单、会话与余额流水不物理删除；注销时删除账号凭据和手机号，匿名保留业务凭证。
- 密码、刷新令牌和模拟验证码只保存摘要；日志不得记录完整令牌、验证码、手机号或机密。
- 高德安全密钥与 TPNS 服务端密钥只存放在服务器环境中，不得进入源码、APK、公开仓库或日志。
- 模拟验证码只能在开发配置中返回，生产配置必须禁用。

## PostgreSQL 与数据运维

- 使用 PostgreSQL 和 QPSQL，不再为第一版选择 SQLite。
- 开发、测试和云端数据库必须隔离，不复用生产凭据或真实数据。
- 业务层通过仓储接口访问数据库，使用参数化查询，不向领域层泄露 QSqlQuery。
- 每次结构变化使用带版本号的迁移；空库必须能完整迁移到当前版本。
- 明确主键、外键、唯一、非空、检查约束、索引和删除策略。
- 后端每 60 秒采集服务器指标，指标保留 7 天；运行日志保留 30 天，审计日志保留 180 天，订单与余额凭证长期保留。
- PostgreSQL 每日备份保留 7 天，每周备份保留 4 周；第一版保存在云服务器本机，并至少验证一次测试恢复。

## Qt 与通信约定

- 最低 Qt 版本为 6.8，Linux 当前安装 Qt 6.8.3；不得无验证回退到系统 Qt 6.2.4。
- REST API 使用版本化路径、统一 JSON 格式和稳定错误码。
- WebSocket 每秒推送充电进度；断线重连后从后端重新获取状态。
- Android 通过原生桥接接入 TPNS SDK；在用户同意隐私政策之后初始化，并正确处理通知权限被拒绝的情况。
- Nginx 终止公网 TLS，后端与 PostgreSQL 只监听受控内部地址或端口。
- 网络和数据库操作不得阻塞 UI 线程；异步流程处理取消、超时、重连和错误反馈。
- 使用 RAII、值语义、智能指针和 Qt 父子对象机制，明确所有权与线程亲和性。
- 用户可见文本进入 Qt 国际化机制；第一版是否交付中英文以 README 待确认项为准。

1. 先解决 README 16.1 中会改变数据模型的价格、排队、站点、设备、订单和规模问题。

4. 实现站点、设备、模拟器、会话、计费、虚拟余额和订单事务闭环。

6. 接入高德地图、定位、服务器监控、备份与云端部署。
7. 完成安全、并发、幂等、断线重连、迁移和恢复验证。

- 使用 Qt 6.8 或更高版本成功配置和构建，相关单元、集成及烟雾测试通过。

- MVP 正常流程以及重复启动、重复结束、余额不足、重复扣款、令牌失效、WebSocket 重连和事务回滚得到验证。
- Android 与管理端在加载、空数据、失败和无权限状态下提供明确反馈。
- 源码、构建产物和日志不包含高德密钥、数据库密码、云凭据或个人敏感数据。
