# 充电桩应用管理平台开发

## 需求依据

开始工作前阅读仓库根目录的 [README](../../../README.md)。涉及范围或技术选择时，再读取 [需求差异与待确认清单](../../../docs/requirements-gap-analysis.md)。

以《01.项目说明书-东软电动汽车充电桩应用管理平台》为基础验收要求。后续问答可以细化和扩展；若与基础要求冲突，必须保留基础项并标为待确认，不得静默删除或把它改成范围外功能。

## 基础产品范围

- Linux + Qt 手机式用户端是基础要求；Android 是已确认的优先开发目标和扩展平台。优先共享 Qt Quick/QML + C++ 代码。
- Linux + Qt PC 管理端必须包含管理员登录、7/30 日营收、今日/月/总营收、电桩状态、模拟远程重启、站点管理、用户冻结和订单查询。
- 平台业务服务覆盖用户、站点、充电桩、排队、订单、计费、钱包、设备控制和数据统计。
- Web + ECharts 大屏与机器学习负荷预测属于最终项目主线，不得作为普通可选功能删除。
- 用户端必须覆盖附近站点、距离排序、站点/设备详情、驾车/步行导航、用户资料、钱包、充电和结算。
- 基础设备状态至少包括闲置、在用和故障；远程重启为模拟操作并记录结果。
- 机器学习最低目标是未来 1/6/24 小时的负荷、空闲桩和高峰时段预测，并向用户端提供推荐、向管理端提供预警。
- 数据传输需要稳定的协议结构、Socket 通信能力、多线程/并发设计、数据安全和完整错误处理。

## 已确认的扩展和约束

- Android 包名为 `io.github.heguangv.chargingstation`，公开仓库为 `https://github.com/heguangV/charging-station-platform`。
- 范围限定北京，暂定朝阳、海淀、丰台三个模拟站点，每站 4 个模拟充电桩。
- 第一版只支持设备繁忙后的即时排队，不支持未来时间预约；设备分配后确认期为 5 分钟。
- WebSocket 与 TPNS 基础通道用于提醒；推送失败不能改变排队和分配事实。
- 使用统一电费与服务费、虚拟钱包和模拟充值，不使用真实资金。
- 用户可以手动结束，或按目标金额/余额上限自动结束。
- 模拟时间倍率默认 60、范围 1～300，只影响新会话，并保存到会话快照。
- 不连接真实充电桩，不接真实短信和支付，不做二维码；但这些约束不能删除基础故障状态、模拟重启和地图导航。
- 三个角色为普通用户、运营人员和系统管理员；所有权限由后端验证。

## 必须保留为待确认的差异

- 说明书要求 Linux 用户端；不得因 Android 优先而删除 Linux 构建目标。
- 说明书指定腾讯地图，当前已有高德 Key；默认腾讯地图，替换需要明确许可。
- 说明书正文写 SQLite、结构图写 MySQL/InfluxDB/MinIO，当前方案选择 PostgreSQL；编码数据库层前确认验收规则。
- 说明书要求手机号免密自动注册、昵称和头像；当前方案是用户名/手机号密码且无昵称。公网不得直接实现可冒用的手机号免密接口。
- 说明书给出 `admin / 123456`；仅可用于隔离演示并强制改密，云端必须安全初始化。
- 确认课程是否要求直接使用 pthread/POSIX Socket，或允许 Qt 网络与线程封装。
- 确认机器学习的数据、算法、语言、指标和最低展示范围。

## 架构边界

- `apps/mobile`：共享 QML 用户端，Linux/Android 平台适配。
- `apps/admin`：Linux Qt 管理端。
- `apps/server`：版本化 API、WebSocket、认证、任务调度和业务服务。
- `apps/dashboard`：ECharts 运营大屏，只访问服务 API。
- `core`：领域模型、应用用例、事务边界和共享协议。
- `infrastructure`：数据库迁移与仓储、地图、推送、模拟设备、文件、日志和配置。
- `ml`：数据生成/处理、训练、推理、模型版本和降级实现。
- `tests`：领域、数据库、API、并发、UI 和端到端测试。

客户端和大屏不得直接连接数据库。UI 不承载权限、计费、余额扣减或 SQL 规则。后端和数据库是设备、排队、订单、计费与钱包的唯一可信来源。

## 关键业务与安全不变量

- 同一设备同一时间最多有一个有效充电会话或待确认分配。
- 开始新充电前必须检查并处理用户的充电中或待结算订单。
- 金额使用最小货币单位整数；充电量使用明确精度的定点值。
- 会话保存价格和倍率快照，配置修改不影响历史或进行中会话。
- 开始、结束、结算、充值、余额调整和设备命令必须具有幂等与审计设计。
- 结算、余额扣减和流水写入使用同一数据库事务。
- 订单、会话与钱包流水不物理删除；注销后匿名保留业务凭证。
- 密码、刷新令牌和验证码只保存安全摘要；日志不记录完整令牌、验证码、手机号或机密。
- 地图、TPNS、数据库和云服务密钥不进入源码、APK、Git 或日志。
- 演示登录和默认管理员不得在公网配置中启用。

## 实施与完成标准

先解决需求差异清单中的 P0 问题，再冻结数据模型和客户端流程。随后依次完成工程骨架、核心业务、管理功能、Android/地图/通知扩展、Web 大屏、机器学习与交付验证。

交付必须满足：

- Qt 6.8 或更高版本可重复构建，数据库可从空库迁移。
- Linux 用户端、Android 目标、管理端、后端、大屏和 ML 的实际完成状态如实标注。
- 用户充电、未完成订单处理、结算、管理员统计、故障与重启形成可演示流程。
- 通信处理超时、重连、重复、非法输入和服务不可用；关键并发和事务得到测试。
- 大屏指标有明确口径；预测有可复现数据、模型版本、评价结果和失败降级。
- README、需求差异、接口、数据库、部署、测试和演示文档与实现同步。
